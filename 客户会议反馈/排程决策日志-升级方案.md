# 排程决策日志 · 升级方案

> 2026-09-22 讨论沉淀。客户要看懂「这一格为什么这样排」，事后也可以把同一份日志交给大模型核对决策。  
> 本方案补 [排程辅助调整与交期协商](排程辅助调整与交期协商-升级方案.md) §5：过程气泡仍是投影，事实源仍是一次 `schedule()` 的运行日志。不另起第二套日志，不另起第二套引擎。

---

## 1. 为什么要做

现在每次倒排已经留下 `ScheduleTrace`：展开、排队、落下、跳过、未安置、半成品、体检。运行日志 `sphinx.schedule_run_log.v1` 会把其中一部分收成 `llm_brief`。

客户和大模型仍然回答不了三个问题：

1. **这一格在试之前，谁已经坐在上面？** 现有事件只有「已占多少版」，没有客户和订单。
2. **这次尝试算成功还是失败，原因用的是哪一句人话？** 成功、休息、排满、撞上最早可排日，混在 `kind` / `skip_reason` 里，英文码客户读不懂。
3. **所以下一步做什么？** 往前一天、换下一张单、还是停下记未安置——这个意图没有写在本条决策上。`llm_brief` 还把「跳过的那些天」摘掉了，审的恰恰是这些失败步。

价值：

| 谁 | 现在 | 升级后 |
|----|------|--------|
| 生管 / 客户 | 看见格子和红条，要自己猜怎么走到这一步 | 按订单展开：试了哪一天哪一组、为什么、成没成、下一步为什么 |
| 验收 | 只能对结果 | 可以对过程：每一步的原因都在闭集里 |
| 外接大模型 | 摘录里缺失败步，容易建议「换一组再试」 | 读完整决策链，只核对倒排规则有没有走错 |

## 2. 设计原则（违反即重写）

1. **日志描述已经发生的倒排，不描述一次搜索。** 品项的组在主数据里定死。游标从交期当天起，同一组一天天往前（`backward_place`）。没有「换一组」「往后一天」「挑一个更优的格子」。
2. **原因码就是客户看到的那句中文。** 闭集，见 §4。禁止英文码加翻译表。代码枚举的值、界面、运行日志、交给大模型的正文，用同一句。
3. **下一步写在本条上，不把下一条再抄一遍。** 本条给出「接下来要做的动作 + 原因码」。下一条决策是这个意图的落实。
4. **只展开正在尝试的那一格。** 前序占用 = 这一天、这一组里已经坐下的订单。不要每步拍整张日历。
5. **仍是纯函数的返回值。** 决策链挂在 `ScheduleResult.trace` 上，由 `append_event` 写入。引擎禁止写文件、禁止 `datetime.now()`。
6. **死区如果把格子改回去，必须另写一章。** `apply_deadband` 发生在落位记录之后。只审落位，会审一份最后没执行的计划。
7. **冲突不是占格失败。** E1–E8 仍是事后体检，只提示不阻断（BR-50）。占格失败只有三句：这天休息、这天已经排满、已经早于最早可开工日。
8. **外接模型只读这份日志，不读界面文案，不改计划，不改交期（BR-27）。**

## 3. 一条决策长什么样

分三种，界面都按「客户 + 订单」收拢。字段名给程序，原因码给客户。

### 3.1 占格（成品、半成品各走一遍）

| 槽 | 含义 | 示例 |
|----|------|------|
| 客户、订单、工单、品项 | 这步在为谁排 | 华润 · SO-004 · WO-… · P2 |
| 成品还是半成品 | 幕 | 成品 |
| 前序占用 | 只列**这一格**里已有的单：客户、订单、版数；并写日产能、已占、还空 | 9/22 · 一部·模具组 · 日产能 100 版，已占 80（张三 SO-001 80 版），还空 20 |
| 当前尝试 | 日期 + 部门·组 | 9/22 · 一部·模具组 |
| 原因码 | 为什么试这一格 | 从交期当天开始 |
| 结果 | 排下了 / 没排下 | 排下了 |
| 本步版数、还剩版数 | 成功才有本步版数；两种结果都写还剩 | 放下 20 版，还剩 80 版 |
| 没排下的原因码 | 仅失败 | 这天休息 / 这天已经排满 / 已经早于最早可开工日 |
| 下一步 | 动作 + 目标（若仍是格子：日期+组） | 同一组再往前一天 · 9/21 · 一部·模具组 |
| 下一步原因码 | 为什么是这一步 | 当天还有空位，本单没排完 |

组名用客户口径：**一部·手工组 / 一部·模具组 / 一部·浇注组 / 二部·手工组 / 二部·模具组 / 二部·浇注组**。日志里不出现 `MANUAL`、`MOLD`。

### 3.2 排队（每张工单一次，还没有格子）

发生在占格之前。说明为什么先排这张。

- 原因码：`交期更晚，先占格子` 或 `这张被钉住，先占格子`
- 下一步：开始占格，目标是该工单交期当天、该品项所属的那一组
- 下一步原因码：`从交期当天开始`

排序仍遵守 BR-25：默认交期降序；插单/改单才钉住优先。日志不把「紧急单优先」写成原因。

### 3.3 半成品要不要开工单（占格之前）

成品全部落完才进入（BR-34）。

| 情况 | 原因码 | 下一步 |
|------|--------|--------|
| 库存盖住毛需求 | 库存够用，不用再做 | 看下一条半成品，或开始排已开出的半成品工单 |
| 净需求 > 0 | 库存不够，要开工单补 | 先排这张半成品；交期 = 成品开工减提前期 |
| 交期怎么来 | 必须在成品开工前做好 | 占格起点用这个应交日，不是成品交期 |

半成品自己的占格与 §3.1 同一张表，幕标成半成品，并写明它服务哪张成品订单。

### 3.4 死区（有基线时才有）

| 情况 | 原因码 | 下一步 |
|------|--------|--------|
| 开工位移 < 死区天数，或工时变化 < 死区比例 | 挪得太少，保持原来的安排 | 这张工单的格子改回基线；其它单保持本轮结果 |
| 超过死区，或是本次触发单 | 变动够大，采用这次的安排 | 保留本轮格子 |

### 3.5 体检

单独一条收束，不插入占格链：红几条、黄几条、未安置几条。原因码：`冲突只是提醒，不改这一轮的格子`。

## 4. 原因码闭集（中文，禁止再翻译）

程序里的枚举值就是左列原文。界面、日志、大模型看到的也是左列。新增原因必须先加进这张表，禁止现场拼一句。

### 4.1 为什么试这一格 / 为什么先排这张

| 原因码 | 何时使用 | 规则 |
|--------|----------|------|
| 交期更晚，先占格子 | 排队，`DUE_DESC` | BR-25 |
| 这张被钉住，先占格子 | 排队，`PIN_FIRST` 且工单在钉住名单 | BR-25 |
| 从交期当天开始 | 本工单第一次占格，格子日期 = 工单应交日 | BR-20 |
| 上一天没排完，继续往前 | 上一步已经放下一部分，余量仍 > 0 | BR-23/24 |
| 上一天没排下，继续往前 | 上一步是休息或已满 | BR-22 / 容量 |

### 4.2 这一步的结果

| 原因码 | 含义 |
|--------|------|
| 排下了 | 当天还有空版，本步吃掉「还剩」和「还空」里较小的那个 |
| 没排下 | 这一格没有放下任何版 |

失败时再带一条，三选一：

| 原因码 | 含义 | 规则 |
|--------|------|------|
| 这天休息 | 日历不是工作日 | BR-22 |
| 这天已经排满 | 日产能减已占 ≤ 0 | BR-23 |
| 已经早于最早可开工日 | 游标 < `earliest_start` 仍有余量，停止占格，记未安置 E1 | BR-21、BR-50 |

### 4.3 下一步为什么这样做

| 原因码 | 下一步动作 |
|--------|------------|
| 当天还有空位，本单没排完 | 同一组，日期减一天 |
| 本单排完了 | 队列里下一张工单；若成品队列空了，进入半成品 |
| 休息日不排，再往前找工作日 | 同一组，日期减一天 |
| 这一天满了，再往前找空位 | 同一组，日期减一天 |
| 最早可开工日之前不能再排 | 本单记未安置，换队列里下一张；不再为它占格 |
| 成品都排完了，开始看半成品 | 进入 §3.3 |
| 库存够用，不用再做 | 不生成半成品工单 |
| 库存不够，要开工单补 | 生成半成品工单，净需求 = 毛需求 − 占库 |
| 必须在成品开工前做好 | 半成品应交日 = 成品开工 − 提前期（自然日） |
| 挪得太少，保持原来的安排 | 死区恢复基线任务 |
| 变动够大，采用这次的安排 | 保留本轮任务 |
| 冲突只是提醒，不改这一轮的格子 | 体检收束，计划保持原样 |

数量一律用**版**（BR-01）。`CREW` 口径的人数已含在 SPH 里，原因码和说明里不出现「再乘人数」（BR-11）。

## 5. 客户看到的一段（示例）

下面是讲解投影，句子来自决策字段，不是模型现写。

> **华润 · SO-004 · P2 · 成品 · 一部·模具组**  
> 排队原因：交期更晚，先占格子。  
>   
> 1. 9/22 这一格已经坐着张三的 SO-001，80 版；日产能 100，还空 20。  
> 试 9/22 · 一部·模具组，因为从交期当天开始。  
> **排下了** 20 版，本单还剩 80 版。  
> 下一步：同一组再往前一天（9/21）。原因：当天还有空位，本单没排完。  
>   
> 2. 试 9/21 · 一部·模具组，因为上一天没排完，继续往前。  
> **没排下**。原因：这天休息。  
> 下一步：同一组再往前一天（9/20）。原因：休息日不排，再往前找工作日。

半成品另起一小节，先写「库存不够，要开工单补」，再写它自己的占格。未安置收在该单最后一步：`已经早于最早可开工日` + `最早可开工日之前不能再排`。

过程 Tab 默认一句结论（这单从哪天排到哪天、还剩多少、有没有未安置），展开后才是逐步。与辅助调整方案里的过程 Tab 共用同一份 trace，避免两套讲法。

## 6. 给大模型的材料

仍是一次运行一份日志，schema 继续 `sphinx.schedule_run_log.v1`，增加 `decisions` 数组。旧的 `trace.events` 保留，决策字段并进事件，避免两份账对不上。

`llm_brief` 改为按决策链渲染 §5 那种正文（含每一次没排下），不再只摘成功落位。算法卡片仍放在简报开头，让模型知道组是定死的、只能往前走。

提问收成这几句，写进 `llm_ask`：

1. 排队原因是不是「交期更晚，先占格子」；只有钉住名单里的单才允许「这张被钉住，先占格子」。
2. 每张工单的第一格日期是不是应交日；之后是不是只往前一天、同一组。
3. 「排下了」时，还剩版数是不是等于放下之前的余量减去本步版数；本步版数是不是不超过这一格的还空。
4. 「没排下」的原因是不是只有休息、排满、早于最早可开工日这三句；前两句的下一步是不是同一组再往前一天。
5. 出现「已经早于最早可开工日」之后，这张单有没有再占格。
6. 半成品是不是在全部成品占格之后；库存够的有没有仍开工单。
7. 若有死区章，最后格子与死区结论是否一致。
8. 指出可疑步骤。禁止建议改客户交期、换组、改用优化求解。

模型结论只回「通过 / 有条件通过 / 不通过」加可疑步骤编号。不写回计划。

## 7. 与现有代码的接法

| 已有 | 本方案怎么用 |
|------|----------------|
| `TraceEvent` / `append_event` | 补：客户、结果（排下了/没排下）、原因码、没排下原因码、下一步、下一步原因码、这一格的占用明细 |
| `backward_place` | 占格决策的唯一写入点。占位时记「谁 + 多少版」，尝试时只读当前格 |
| `sort_work_orders` | 每张工单一条排队决策 |
| `expand_semi_from_line` | 半成品开不开工单的两条原因码 |
| `apply_deadband` | 落位之后补死区章，使日志与最终 `tasks` 一致 |
| `detect_conflicts` | 只贡献体检收束，不改写占格结果 |
| `build_schedule_run_log` / `render_llm_brief` | `decisions` + 含失败步的中文简报 |
| 过程 Tab / `NarrationBar` | 投影 §5，带 `run_id` + 决策序号 |

占格账本：现在的 `occupied` 只存版数。落位成功时追加 `{客户, 订单号, 工单号, 版数}`，键仍是部门 + 组 + 日期。失败步不写入账本。锁定任务在开排前先入账（BR-26），前序占用里客户写「已锁定」。

每张工单占格结束，可附一行该组在「应交日 → 最早可开工日」窗口内的占用小结，供模型看棋盘。窗口外的格子不展开。

## 8. 明确不做

- 英文原因码，或中英两套码
- 每步导出整张日历
- 把倒排写成「在多个格子里选择」
- 用模型生成原因码或下一步
- 第二份日志、第二套排程
- 决策日志里改交期、改组、触发重排
- 把 E2–E8 写成某一次占格的失败原因
- 自由提问的排程对话框（仍按辅助调整方案：模型只做事后核对）

## 9. 落地节奏

### A. 引擎记全（先有账）

- `TraceEvent` 补齐 §3 的槽，原因码用 §4 原文
- `backward_place` 每一步写结果、前序占用、下一步
- 排队、半成品开关、死区、体检按章写入
- pytest：固定一张「休息 + 部分落下 + 排满 + 未安置」的输入，断言原因码序列与还剩版数。原因码不在闭集里即失败

### B. 运行日志给模型

- `decisions` 进 `sphinx.schedule_run_log.v1`
- `llm_brief` 含失败步；`llm_ask` 换成 §6
- 现有 brief 断言改成对中文原因码

### C. 客户能展开看

- 过程里按订单折叠，展开为 §5
- 点一步，左侧对应日期+组脉冲
- 与辅助调整方案的过程 Tab 合并，不新增入口

验收口令：

> 随便点开一张单，能看见每一天试的是哪一组、格子上原来是谁的单、这步为什么、排下了还是没排下、下一步为什么。这些原因都是固定的中文短句。把同一份日志交给模型，它只能按这些短句核对，不能另编一套排法。

## 10. 业务红线（本方案自检）

- **BR-20**：第一格从应交日当天起
- **BR-21 / BR-47**：早于最早可开工日则停并记未安置；日志不把没排下的版写成已排
- **BR-25**：默认原因码是「交期更晚，先占格子」
- **BR-27**：日志、简报、模型结论都不写 `so_order.due_date`
- **BR-34**：半成品章在成品占格之后
- **BR-40**：本方案不触发全量重排
- **BR-50**：没排下和红冲突都不 `raise` 中断排产
- **BR-01 / BR-11**：版；CREW 不再乘人数

## 11. 讨论记录

1. **原因码用中文。** 客户要直接读。枚举值等于界面上的那一句，不做英文码再翻译。
2. **决策是确定的往前走，不是搜索。** 组不选；失败后只有往前一天或停手换单。
3. **下一步挂在本条。** 写意图和原因，不复制下一条全文。
4. **前序只展开正在试的那一格，并写明是谁的单。** 整表快照会把日志撑爆。
5. **死区单独成章。** 否则模型审的是被回写之前的格子。
6. **简报必须带上没排下的步。** 现在的摘录把这些步丢掉了。
7. **模型只核对闭集，不提出另一种排法，不改交期。**
