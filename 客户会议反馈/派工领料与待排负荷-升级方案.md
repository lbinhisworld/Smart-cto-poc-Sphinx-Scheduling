# 派工领料、最快方案与待排负荷 · 升级方案

> **2026-09-22 第二次演示之后，对外范围以 [第二次演示后-完整升级方案.md](第二次演示后-完整升级方案.md) 为准。** 最快方案 what-if、待排缺口一次占库仍按本文。未排汇总的对外三类、半成品完成标识以完整方案 §4.3、§4.4 为准。  
> **2026-09-23** 派工导出改按客户《模具组》生产排程表头，包材列与派工在同一张表，不再另附领料表。领料按日分摊仍只用于齐套和待排缺口。下文 §3.3 的第二张领料表不再作为导出格式。
>
> 2026-09-22 客户反馈沉淀。三件事都要能拿给现场用：下到产线的派工单长得和他们原来的《组排程》一样，并写明这一班要什么料、要多少；交期排不下时，给出一份最快能做完的方案，交给销售去谈；人排不完时，能看见已经排完的有多少、还没排的有多少，以及没排的那些要多少料、多少工时。  
> 本方案不另起排程引擎。派工单仍是当前计划里的 `wo_task`。最快方案仍是一次倒排的提案，不写订单交期。待排负荷用现有换算、BOM 和工时函数汇总，不把没排的单硬排上日历。

## 1. 为什么要做

客户现在没有 MES。《组排程》Excel 同时是计划、派工单和报工底稿。排程结果如果不能按这张表交下去，产线不会用。交期谈不下来时，销售要的是一份能拿去跟客户说的方案，不是只有一条红字。人一天排不完所有单时，生管要知道剩下的单还压着多少料和工时，否则「先排一部分」只是把积压藏起来。

对照当前 POC：

| 客户要的 | 现在 |
|----------|------|
| 派工单表头与原来 Excel 一致 | 能导出 xlsx，列是订单号、客户、品项、工单、墙钟工时等内部字段；不能按组、按日期导出 |
| 派工单写明产线领什么、领多少 | BOM 和齐套在订单抽屉里，按整单、按版；派工单上没有 |
| 交期做不到时给出最快完成方案，销售去谈 | 有最快可完成日，过程里可以发协商口径；没有按这个日期排出的任务草案 |
| 已排 / 待排各有多少张 | 驾驶舱和订单页有待排程、排程中、生产中的张数 |
| 待排的料和工时 | 没有汇总。工时只在任务落到组×天之后才有 |

价值：

| 谁 | 现在 | 升级后 |
|----|------|--------|
| 产线 | 看不到和原来一样的派工单，也不知道这一天领什么 | 按组、按日期拿到《组排程》；旁边一张领料，料和数量对得上当日版数 |
| 销售 | 只听到「排不了」或一个日期 | 拿到最快方案：建议交期、哪几天、哪一组、多少版、要多少料和工时 |
| 生管 | 知道池子里有几张单 | 知道本轮排完几张、还剩几张，剩下的毛需求料和需求工时是多少 |

## 2. 设计原则（违反即重写）

1. **《组排程》十列逐字一致，不夹私货。** 列名与列序固定为规格 §8.4：`生产日期 | 组 | 型号 | 品名 | 单位 | 计划生产数量(版) | 人力 | 生产人员 | 顺序 | 备注`。领料不插进这十列，单独一张表，用同一行的日期、组、型号、顺序对上。
2. **料从现有 BOM 来，数量先归一到版。** 用 `md_bom_line` 和现有毛需求公式。半成品、外购件都列出，并标明是自做还是领用。禁止在派工单上另编一套物料名或单位。
3. **同一工单各日领料加总等于整单毛需求。** 按当日任务版数分摊，最后一天吃掉取整尾差。禁止每天各自向上取整，导致产线多领。
4. **最快方案是提案，不是已发布计划。** 客户交期仍是锚（BR-27）。官方结果仍按原交期倒排；做不到就停，并给出最快可完成日（BR-47）。提案用这个日期再做一次 what-if 倒排，不落成当前计划，不发布。
5. **待排负荷不是第二次排程。** 待排订单不占日历、不生成 `wo_task`。料用毛需求汇总；工时调用 `hours_wall` / `hours_man`，标成「需求工时，未落到日期」。
6. **缺口不能把各单短缺相加。** 每单各自对同一库存算一遍，库存会被重复使用。待排缺口必须用一次占库，按交期从早到晚走完待排订单。毛需求可以按单相加。
7. **已排和待排按计划事实划分，不按按钮颜色。** 见 §5.1。排程池里还没跑过的单，既不算已排产，也不算待排产。
8. **人·时和墙钟分开。** 待排汇总、最快方案、派工单备注里若出现工时，墙钟与人·时分列。`CREW` 口径禁止在 `hours_wall` 之外再乘一遍人数（BR-11）；人·时仍是墙钟乘计划人数（BR-12）。

## 3. 派工单：表头对齐，并带上当日领料

### 3.1 谁可以导出

下到产线的派工单只来自**已发布**的计划（订单已在生产中、工单 `RELEASED`）。排程页上未发布的试排可以导出预览，文件名和首行写明计划版本和「未发布，不得下发」。空计划仍只给一句「请先倒排」，不造空表头冒充派工单。

导出范围按规格 P6：先选组和日期区间，再导出。不选则默认当前计划里全部已发布任务，仍按组、按生产日期排序。

### 3.2 《组排程》怎么填

一行 = 一条 `wo_task`。

| 列 | 取值 |
|----|------|
| 生产日期 | `task_date` |
| 组 | 客户口径：一部·手工组 / 一部·模具组 / 一部·浇注组 / 二部·手工组 / 二部·模具组 / 二部·浇注组。表内不出现 `MANUAL`、`MOLD` |
| 型号 | 品项编码 |
| 品名 | 品项名称 |
| 单位 | 版 |
| 计划生产数量(版) | 当日 `qty_board` |
| 人力 | `crew_plan` |
| 生产人员 | 留空。系统只有人数，没有这一班是谁。不编姓名 |
| 顺序 | `seq`（同日、同组） |
| 备注 | 有人工改期/改量原因就写原因；否则空。不把冲突码、版本号塞进备注 |

订单号、客户不进这十列。领料表和文件名可以带计划版本，方便对账。

### 3.3 领料表

第二张表，表名「领料」。每一行对上《组排程》的一行任务，一种子件一行。

| 列 | 含义 |
|----|------|
| 生产日期、组、型号、顺序 | 与《组排程》同一行，用来对上 |
| 子件编码、子件名称 | `md_bom_line` 的子件 |
| 角色 | 半成品（自做或领库存） / 外购（领用） |
| 数量(版) | 这一天这一任务分到的毛需求 |
| 整单毛需求(版) | 该工单这种子件的毛需求，便于领料员核对加总 |

没有 BOM 行、只有工艺路线上的半成品时，领料表仍列出该半成品一行，数量用现有半成品毛需求，不留空表假装不用料。

成品任务才领料。半成品任务的「料」若 BOM 未展开到更下一层，领料表写「无下级子件」，不虚构原料公斤数。客户若要原料、包材的公斤或采购单位，等他们确认换算和清单后再加列；本方案不先写上。

### 3.4 数量怎么分到每一天

1. 整张成品工单先算每种子件的毛需求（与齐套、展开同一公式，含损耗，结果为版）。
2. 按该工单各日任务版数占计划版数的比例分到每一天，数量用整数版。
3. 前几天向下取整，**最后一天 = 整单毛需求 − 已分配**，保证加总相等。
4. 外购件和半成品同一规则。半成品净需求（扣库存之后要不要开工单）仍只在排程和齐套里算，领料表给产线的是毛需求，避免现场按净需求少领。

## 4. 交期无法满足时的最快方案

现有 [排程辅助调整与交期协商](排程辅助调整与交期协商-升级方案.md) 已经规定：红了之后把最快可完成日写成口径，发给销售，销售回确认日，生管改锚后再倒排。本方案补上口径里缺的那份**方案**，不重做协商闭环。

### 4.1 方案是什么

仅当这张单在本轮倒排里未安置完，或半成品赶不上，且最快可完成日**晚于**客户交期时，才生成方案。最快日不晚于客户交期的，沿用现有口径：交期本身够，不发给销售。

方案是一次 what-if：

1. 锚改成当次算出的最快可完成日。这个日期只存在提案里，不写入 `so_order.due_date`。
2. 仍用现有倒排（先成品、后半成品，默认交期降序；若本轮是插单则沿用钉住优先）。不新做正排，不换求解器。
3. 范围只含这一张订单。不为了让它变绿去挪其他已发布任务。
4. 结果不调用发布，不替换当前计划版本。人关掉就丢。

方案上要有销售能转述的事实，全部来自这次 what-if，禁止手写日期：

- 客户原交期、建议不早于哪一天
- 卡在哪：未安置，或半成品来不及（沿用 E1/E2 的那句人话）
- 提案上的开工日、完工日、组、各日版数
- 墙钟工时、人·时（任务上已有的两个数，分开写）
- 与 §3 同一规则的领料汇总（整单，不按未发布的日历假装已经下发）

官方看板保持原交期的红。方案页标题写「提案 · 未改交期 · 未下发」。

### 4.2 怎么交到销售

过程里现有的「协商交期」多带上这份提案摘要。发给销售的待办和企微模拟仍走 S6，正文增加三句：建议交期、要做几天、主要用料（子件名 + 版数）。销售回确认日、生管改锚、人再倒排，仍按交期协商方案，不在这里自动改锚、不自动重排（BR-27、BR-40）。

若提案在最快日上仍然排不下（日历或齐套比「最快可完成日」更紧），方案页写明「最快日试排仍未排完」，并把新的未安置原因附上。禁止把这份失败试排说成已经可做。

## 5. 已排产与待排产

人员不够、不能把订单全部排完。排程池继续由人勾选，系统不自动把待排订单排进去。本方案只把两边的账算出来。

### 5.1 三格，对外讲两格

| 格子 | 判定 | 给客户的说法 |
|------|------|----------------|
| 已排产 | 当前已发布计划，或当前计划版本里已经有该订单的任务，且没有未安置完的红 | 这张单已经有可以执行或正在执行的计划 |
| 待排产 | `schedule_phase = PENDING`，从未进入当前计划 | 还没排 |
| 池内未跑完 | 已在排程中，但当前计划没有它的任务，或有未安置红 | 人已经选进来，这一轮还没排完。**不计入已排，也不计入待排** |

驾驶舱和订单页都展示这三个数，避免把「在池子里」说成「已经排完」。点数字进对应列表。

已排产列表至少有：订单、客户、品项、交期、计划开工、计划完工、是否已发布。工时用该单已有任务的墙钟与人·时合计，不再重算一遍别的公式。

### 5.2 待排产要的料

只统计待排产，不含池内未跑完（那些单的料会在下次倒排时按池内顺序占库，提前并进待排会算重）。

- **毛需求**：每张待排订单用现有展开算子件毛需求（版），再按子件相加。这是「这些单一共要多少料」。
- **缺口**：待排订单按交期从早到晚，用**一次**库存快照依次占用。外购件缺口、半成品净需求分开列。禁止把每张单自己的短缺相加。
- 缺少换算链、展不开的订单单独计数，不把它们的料当成 0。

列表两层：上面是子件合计（编码、名称、角色、毛需求版、缺口版）；点开是哪些待排订单贡献了这些版。

### 5.3 待排产要的工时

对待排订单的成品计划版数（含损耗，与展开相同）调用 `hours_wall` 和 `hours_man`：

- 组、SPH、换算链、标准人数都用主数据，不另写除法。
- 需要半成品且净需求大于 0 时，半成品工时用同一对函数另计，和成品分列，再给一个合计。库存已经盖住的半成品不计半成品工时。
- 数字标成「需求工时」。不生成任务日期，不占组×日容量，所以它不是排程结果，也不能拿去和日历上的已排工时比谁更「准」。
- 展示：墙钟小时、人·时，按组小计，再按订单可展开。

池内未跑完不进这个合计。已排产的工时只来自任务，不来自这套估算。

| 位置 | 加什么 |
|------|--------|
| 排程页「导出派工单」 | 先选组、日期；导出两个表。未发布时按钮仍在，下载的是预览 |

## 7. 数据与接口（建议）

不新造派工业务表。领料和待排汇总都是读出来的。

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/plan/export-dispatch?group=&date_from=&date_to=` | 已有路径补上筛选。已发布写正式文件；未发布在表头标明预览 |

## 8. 明确不做

- 改《组排程》十列的名字或顺序来凑内部字段
- 在「生产人员」里编造姓名，或在本方案里做排班到人
- 把原料公斤、包材采购单位写上派工单（BOM 没有这一层之前）
- 用最快方案覆盖当前计划、发布到产线，或写回订单交期
- 为最快方案去重排其他订单、加班、挤占（那些仍走交期协商方案里另外的策略卡）
- 把待排订单自动加入排程池，或为了算工时给它们生成 `wo_task`
- 全量重排作为导出或统计的副作用
- 正排、有限产能求解、优化库

## 10. 落地节奏

### A. 派工单能下发（产线最先用）

- 《组排程》十列与规格逐字一致，组名用中文
- 领料表按日分摊且加总等于整单
- 可选组、日期；未发布文件标明预览
- 用现有种子跑一张已发布工单：十列、领料行、各日数量之和与整单毛需求一致

### B. 最快方案交给销售

- 交期晚于客户要求的单，能开出提案（日期、组×日版数、工时、领料）
- 提案不改交期、不替换当前计划
- 协商发送时，销售待办里看得到这三句事实
- 演示仍用现有会排红的那张单，台词见 §12

### C. 待排负荷

- 三格张数在驾驶舱和订单页一致
- 待排毛需求可按子件展开到订单
- 待排缺口是一次占库，不是各单短缺之和
- 需求工时分墙钟和人·时，并写明未落到日期

验收口令（对客户）：

> 下到产线的表和原来的《组排程》是同一排表头，当天要领的料在旁边那张表上，各天加起来等于这张单的用量。交期排不下时，系统另给一份按最快日期试排的方案，销售拿去谈；没谈成之前，原交期还在，计划也不改。排不完的单还在待排里，能看见它们还要多少料、多少工时，系统不会偷偷把它们排进去。

## 11. 业务红线（本方案自检）

- **BR-01 / BR-03**：派工数量、领料、待排料都先到版，换算走换算链
- **BR-11 / BR-12**：待排工时只经 `hours_wall`、`hours_man`
- **BR-27**：最快方案、导出、统计都不写 `so_order.due_date`
- **BR-34**：提案仍先成品、后半成品
- **BR-40**：导出和统计不触发重排；提案不是默认计划
- **BR-47**：原交期做不到的官方结果仍然停；提案失败时不得说成可做
- **BR-50**：待排和红单只展示，不阻断其他人继续排已选的池

## 12. 演示台词

1. 「这是下给模具组某一天的派工单，表头和你们现在的《组排程》一样。旁边是这一天要领的料，单位是版，几天下来加总等于这张单的毛需求。」
2. 「这一张客户要的日期排不下。正式计划仍然挂着原交期。这份是按系统最快能完成的日期试排的方案，还没下发。」
3. 切到销售：「待办里是建议日期、要做的天数和主要用料。你们去跟客户谈。谈成之后生管才改交期，再排一次。」
4. 打开待排：「今天人手只排了池子里这些。下面这些还没排，料和工时是需求，不是已经占上日历的计划。」
