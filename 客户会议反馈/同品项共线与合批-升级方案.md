# 同品项共线与合批 · 升级方案（A→C）

> 并行专题，不替代会议总计划 Wave 3（二部拆组）/ Wave 4（设备+关键岗）/ Wave X（工艺口径与量产成本隔离）。  
> 原则：没合单不要画成一张 WO；真合批必须人确认。禁止写回 `so_order.due_date`（BR-27）。一期不做 APS。

## 1. 为什么要做

`SHARE_20_4` 只保证订单行集合相交。此前场景单不按行展开，引擎只排表头第一件；同品项多单各自倒排，客户在看板上看不到「系统考虑了共线」。

## 2. 三步

| 波次 | 做什么 | 对外一句话 |
|------|--------|------------|
| **A** | 场景单按行进排程 | 四件核心都出现在看板上 |
| **B** | 识别同组同日同品项，换色 + 并线决策 + 点数/版数 | 共线了，但还没并成一张单 |
| **C** | PMC 确认后才生成 LOT | 已合批点数/版数与识别数分开报 |

一个**并线点** = 组 × 日 × 品项。任务量 = 该点 `qty_board` 之和（版）。

## 3. 视觉

- B：青绿并线色（`--coline`），角标 `P1 · 3单 · 共 N 版`。同格未共线品项保持原色。冲突红优先。
- C：更深/实心并线色，角标 `LOT · P1 · 已并 3单`。

## 4. 过程与结果

每条共线固定：看见哪些单 → 并线决策 → 本点单数/版数。收束句：

> 本轮在 K 个点上实现并线，合计 M 版（涉及 N 张订单、S 个品项）。

C 另报「已确认合批 K' 点 / M' 版」，不与 B 混成一个数。
