## 1. 为什么要做

会上要的是一条能演的销售过程：商机分级、打样有客户反馈、报价按公司规则、合同挂订单、回款能看见、大客户走项目。交期试算已经能点。

现场不满的是过程。商机列表只能看种子里写好的阶段，销售没法指出「这张单现在在打样、报价还是签单」，点进去也没有这一环节的记录。财务和销售如果看同一屏，成本又会露给不该看的人。

| 现在能演 | 演不了 |
|----------|--------|
| 客户档案、360、商机列表（阶段是种子） | 一行看清打样 / 报价 / 签单走到哪 |
| 样品追加环节、轮次、证据图、定稿结案 | 从商机大盘点开该环节 |
| 漏斗各阶段条数 | 同一张单，销售、财务、总监点开看到的内容不同 |
| 报价单手工填单价、提交审批 | 按贵司报价表自动算价 |
| 合同必挂、回款手工登记 | 金蝶收款自动进合同 |
| 总经理看项目大盘、填完成日 | A 级签单后转到项目大盘 |
| 交期试算 | — |

业务员登录名是「李业务」，列表却按「陈雨桐」过滤。销售角色进去对不上自己的单。

## 2. 设计原则

1. **一块商机大盘，不按角色拆成三页。** 一行一张商机，列是打样、报价、签单。
2. **格子状态由单据推导。** 样品结案则打样格完成，报价通过则报价格完成，合同生效则签单格完成。上一列完成不会自动建出下一列的单据。
3. **进度和明细分开授权。** 能看见这行的人，都能看见三列走到哪了。点开的事实按角色裁剪，由接口删掉，不靠页面把数字藏起来。
4. **旧阶段名不进大盘。** 「线索 / 商机 / 方案 / 谈判」不再做一排格子，也不再让人维护第二套阶段。结案另记：进行中 / 成交 / 丢单。丢单必须写原因。
5. **商机大盘停在签单。** A 级且总监确认后，才进入现有项目大盘（立项、采购、试机、投产）。两块板不并成一行。
6. **报价规则等客户那张表。** 没有表就继续手填单价。财务在报价格里看到的成本，只用现有计划人工（人·时 × 标准单价），不写成实际材料成本。
7. **金蝶真同步、企微自动摘聊天，不在本方案。** 回款仍手工登记；跟进由人写。
8. **不写客户交期。** 商机预计成交日、项目完成日都不是 `so_order.due_date`。

## 3. 商机大盘

形态对齐现有项目大盘。格子上不写金额。

| 列 | 格子上 | 点开之后 |
|----|--------|----------|
| 打样 | 未到 / 进行中 / 已完成，加日期 | 轮次、客户反馈、证据。沿用样品步骤 |
| 报价 | 同上 | 报价出没出、过没过；售价、计划人工、差额只给有成本权限的角色 |
| 签单 | 同上 | 合同号、已收 / 待收。沿用合同与回款登记 |

状态怎么来：

- 未关联样品、报价单或合同 → 未到
- 已关联且未结案 / 未通过 / 合同未生效 → 进行中
- 样品结案、报价通过、合同生效 → 已完成，日期取单据上的完成日
- 当前环节 = 最右边一个「进行中」；三列都已完成 → 整行成交
- 丢单是整行结案，不是第四列。原因用：价格、交期、样品未过、客户取消、其他

点无权查看的格子：抽屉只留「进行中」或「已完成于某日」，并写无权查看明细。接口不返回明细字段。

跟进（拜访 / 电话 / 微信、下一步、下一步日期）写在行首，不占一列。业务员和销售总监看得到，过期标黄。财务的行首只有客户名和三列状态，没有跟进正文。

### 3.1 谁看哪一行

| 角色 | 行 |
|------|----|
| 业务员 | 只看自己负责的 |
| 销售总监 | 全部商机 |
| 财务 | 全部商机 |
| 总经理 | 全部商机 |

业务员的过滤用当前登录人的显示名。登录「李业务」就看李业务，不再写死陈雨桐。

### 3.2 谁点开能看什么

| 角色 | 打样明细 | 报价状态 | 报价成本（售价、计划人工、差额） | 签单明细 |
|------|----------|----------|------------------------------------|----------|
| 业务员 | 能看、能记 | 不能 | 不能 | 不能 |
| 销售总监 | 能看 | 能看、能关联报价单 | 不能 | 能看 |
| 财务 | 不能 | 能看 | 能看 | 能看已收 / 待收 |
| 总经理 | 能看 | 能看 | 能看 | 能看 |

业务员仍能从格子颜色知道已经到报价或签单，只是点不开价和合同。

若客户改口要业务员自己填报价、只是不能看成本：不改大盘布局，只把「报价状态」授权加给业务员。成本仍只给财务和总经理。

没有已发布计划工时的品项，报价格写「尚无计划人工」，不估一个数。

### 3.3 和项目大盘的分界

A 级由销售总监手标，不按金额自动升级。总监确认后，签单格显示「已转项目」，进入现有项目大盘。B/C 走普通订单，不进项目大盘。

销售和销售总监能看自己负责的项目行并登记完成日。总经理看全部。项目完成日不写订单交期。交排程仍由生管在排程里做。

## 4. 做到哪一步

### A. 商机归到登录人，并能记跟进

1. 新建商机：客户、名称、金额、预计成交日、负责人。负责人默认当前登录人。
2. 写跟进：日期、方式、发生了什么、下一步、下一步日期。
3. 丢单：必填原因。成交不在这一步手改阶段，等三列都完成后由大盘标出。
4. 种子里给李业务留一条有跟进、下一步已过期的商机。

客户档案本步仍不新建、不合并。疑似重复继续只提示。

### B. 商机大盘

- 新页面「商机大盘」。一个接口返回行、三格状态；明细只在该角色有权时出现。
- 授权写在配置里（角色 × 环节 × 能否看明细 / 能否看成本），不写在页面判断里。
- 打样格复用样品步骤，报价格复用报价单，签单格复用合同与回款。
- 总监名单：超过 N 天没有跟进的商机。N 演示默认 7 天，放配置。

### C. A 级转项目

按 §3.3。签单格出现「已转项目」。销售菜单能进自己的项目行。

### D. 报价规则（不挡 B）

客户给出报价规则或通用报价表之后，报价行按表算单价，人可以改并留下原因。表没到之前，D 不做。

### 明确晚于本方案

- 金蝶 K3 收款自动同步。POC 继续手工登记回款。
- 企微聊天自动摘成跟进。
- 道一云全量替换、自定义审批流、字段权限设计器。
- 客户新建、查重合并、线索池公海。

## 5. 演示脚本

**A 做完：** 用「李业务」打开自己的商机，看到下一步过期，补一条微信跟进，下一步改到三天后。列表里没有陈雨桐的单。

**B 做完，同一条商机：**

1. 业务员看大盘：打样格点得开轮次；报价格、签单格只有状态，没有金额。
2. 切财务：报价格点得开，能看见售价和计划人工差额；打样格没有反馈正文。
3. 切销售总监：签单格能看合同；报价格没有成本差额。超过 7 天没跟进的行能筛出来。

**C 做完：** 总监把一条标成 A 并确认，项目大盘多一行。业务员能看见自己的这一行并填一个完成日。

口令：大盘先回答走到哪一列；点开才是这一环节的记录；销售屏幕上不出现成本和合同金额。

## 6. 与现有代码的接法

| 已有 | 本方案 |
|------|--------|
| `crm_opportunity` 只读列表 | 能新建；跟进另表；结案结果与丢单原因 |
| `_sales_filter` 写死陈雨桐 | 改为当前演示用户显示名 |
| `crm_sample_step` | 打样格明细 |

| 合同 / 回款登记 | 签单格明细 |

| CTP、新建订单必须挂有效合同 | 不动 |

## 7. 明确不做

- 用本 POC 替换道一云
- 按角色各做一块布局不同的商机看板
- 再维护一套「线索 → 成交」阶段，让人一格格点过去
- 打样结案后自动建报价单，或报价通过后自动建合同
- 按金额自动标 A 级
- 没有报价表就编自动报价公式
- 把计划人工写成实际材料成本
- 金蝶真实收款接口、企微 AI 摘聊天
- 接口把成本发给销售，只靠样式藏起来
- 任何路径写 `so_order.due_date`

---

## 8. 落地顺序

1. **A**：跟进、丢单原因、数据范围改到登录人。
2. **B**：商机大盘。同一条商机，业务员、财务、总监点同一格，明细按 §3.2 不同。
3. **C**：手标 A/B/C，A 级进项目大盘。
4. **D**：客户报价表到了再做。

B 的验收：三列状态与样品、报价单、合同一致；业务员的响应里没有售价、计划人工、合同金额；财务的响应里没有打样反馈正文；订单交期零次被这条链路写入。

---

## 9. 仍要客户拍板（不挡 A、B 的默认）

- A/B/C 是否同意由销售总监手标。若要按金额或其他规则自动分，另给规则再做。
- 丢单原因是否就用：价格、交期、样品未过、客户取消、其他。
- 报价规则表（与演示控制台待确认 Q13 同一件事）。没表则 D 不做。
- 「超过几天算没跟进」演示用 7 天。若公司有拜访周期，改配置。
- 业务员是否连「报价出没出」都不能看。方案默认不能；若要业务员填报价、只隐藏成本，只改授权表。
