# 订单交付故事线 · 升级方案

> 并行专题：改造排程「订单视图」，不替代派工视图（组×日），不改倒排引擎（BR-27）。

## 1. 目标

客户按**订单**看排程结果：纵向订单卡 + 横向工单（WO）节点链，Tab 区分「交期内可满足 / 无法满足交期」，避免在统一日期大表上横向拖动。

## 2. 形态

- **外层**：订单圆角卡片（订单号、销售、明细摘要、客户交期、计划交付日）。
- **内层**：WO 节点链（日期、工作中心、品项、计划版数/未排余量、墙钟、计划人工成本），节点间 `→`。
- **Tab**：与交期协商同一口径（E1/E2、unplaced、plan_end vs due、最快可完成日）。
- **未排程**：勾选但本次计划无 WO 的表头单，底部灰区。
- **经典矩阵**：折叠保留原 `OrderScheduleBoard`（订单×日期）供 PMC。

## 3. 节点定义

- **一节点 = 一张 WO**；排序：依赖拓扑（半成品→成品），否则 SEMI 在前、按 `plan_start`。
- 表头聚合：`SO-S001#L1` 归并到 `SO-S001`。
- 版数为**倒排计划**，非报工实绩；有 `qty_board_done` 时另展示已完工（Wave 2）。

## 5. 验收剧本

1. SO-002：可满足 Tab，二部 S2 → 一部 P2。
2. SO-004：无法满足 Tab，E1/E2 + 最快可交日。
3. SO-303：三个 SEMI + 成品顺序正确。
4. 场景展开单：一表头一卡。
5. 未参与倒排：未排程区。

## 6. 话术

- 节点版数 = 计划，不是车间报工完成（除非已展示已完工版数）。
- 工作中心名仍为一部/二部×组，正式工序树待 Wave 3。
