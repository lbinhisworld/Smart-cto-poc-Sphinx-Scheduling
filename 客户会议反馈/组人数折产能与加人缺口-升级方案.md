# 组人数折产能与加人缺口 · 升级方案

> 2026-09-23 讨论沉淀。客户要的是：同一工艺只有固定人数（例如 4 人），这人数要限制排产；并且能按组改人数，看出要不要加人、加几个。  
> 本方案不另起排程引擎，不点名到人。倒排仍是现有 `schedule()`。人数只改组日历上的在编，产能和缺口都从这次倒排算出来。交期仍是锚，禁止写回 `so_order.due_date`（BR-27）。  
> 与 [第二次演示后-完整升级方案.md](第二次演示后-完整升级方案.md) §8 的关系：§8 是「谁在哪一天做哪一单、用剩下的小时填另一品」。本方案不做那件事。本方案只回答「这一组有几个人、因此一天能做多少、还差几个人」。

---

## 1. 为什么要做

昨天会上说的是：相同工艺的人是有数的，排产要受这个数限制。今天对齐的用法是：计划按组设定人数，系统把人数折成当天能做的量；单子排完之后，客户能看见差多少人，而不是自己心算。

对照当前 POC：

| 客户要的 | 现在 |
|----------|------|
| 一组 4 个人，当天产能按这 4 个人封顶 | 组日历上有 `headcount`（演示里各组都是 5），倒排算当天能排多少版时不读它 |
| 改人数就改产能，便于试「加几个人」 | 单人口径用的是这张工单自己的 `crew_plan`，不是组在编。多人配合口径的产量是标定好的，改在编不改产量 |
| 排完告诉我要加几个人 | 只在计划人数超过在编、或同一天各单人数加总超过在编时出提示。没有缺口，也没有「加 N 人后再排一次」 |

人数今天进系统的位置：

- 单人口径（`SINGLE`，BR-10）：小时产能 = 单人标准小时产能 × 这张工单的计划人数。
- 多人配合口径（`CREW`，BR-11）：小时产能 = 标准小时产能本身。人数已经含在标定里，禁止再乘。计划人数和标定人数不一致，只出黄色 E8，不停止排产。
- 人·时 = 墙钟 × 计划人数（BR-12），用来算成本和提示，不决定这一天还能不能再排。
- 组日容量（BR-13）= 向下取整（有效工时 × 小时产能）。有效工时 = 日工时 ×（1 − 预留比例）。占用按版累加。
- 出勤实到人数可以按比例缩小「墙钟上限」的提示，但倒排用的组日容量不走这条比例。

所以「只有 4 个人」目前只在提示里出现。标准产能和工时如果事先按这 4 个人标定过，版数上限会间接像那么多；系统不会因为在编是 4，就把多出来的单判成做不了。

价值：

| 谁 | 现在 | 升级后 |
|----|------|--------|
| 计划 | 改组人数，格子上的版数不变，只能看提示 | 单人口径下，人数直接决定这一组当天的人·时，从而决定能排多少版 |
| 计划 / 总经办 | 自己估要加人 | 排完看到一张缺口：现有几人、差多少人·时、要加几人；可按试加的人数再排一版，看哪些来不及的单变得交期内可做 |
| 生产 | 派工单上已有计划人数 | 仍只拿到人数和人·时。名单继续由生产填，本方案不编姓名 |

## 2. 设计原则（违反即重写）

1. **组在编是产能参数，任务上的计划人数不是。** 同一组、同一天，能投入的人是日历上的在编（有实到则用实到）。工单上的 `crew_plan` 仍表示这一单打算用几个人一起干，并且不得超过组在编（BR-14）。它不再单独决定这一天的版数上限。
2. **先看产能口径，再折人数。** 单人口径按人数线性折。多人配合口径禁止把「加 1 人」算成多一份产量（BR-11）。口径没填准，加几个人这个数不许出。
3. **同一组同一天，不同品项共用的是人·时，不是版。** 品项标准小时产能不同，把版数加在同一个上限上会算错。单人口径的占用改记人·时。看板上仍显示版数。
4. **缺口是给客户看的数，不是自动改计划。** 算出要加几个人之后，当前计划、组在编、订单交期都保持原样。试加人数只在内存里再排一次，可丢弃。
5. **交期仍只由人改。** 加人试排不写 `so_order.due_date`（BR-27），也不替换已发布计划（BR-40）。物理上加人仍做不到时，保持现有最快可完成日，禁止硬排（BR-47）。
6. **人数不足只提示，不阻断。** 与 E1–E8 一样是软约束（BR-50）。倒排照常落位；落不下的仍是未安置。缺口写在结果旁边。
7. **不点名，不拆剩余小时去填另一品。** 「4 个人一天约 10 小时，做完 A 再用 B 填满」以及生产人员名单，仍按完整方案 §8 只评估，不进本方案。
8. **数量仍先归一到版**（BR-01）。墙钟和人·时继续分字段（BR-12）。禁止用 float 比较工时。加人的人数向上取整。

## 3. 人数怎么变成当天产能

### 3.1 这一组这一天有多少人·时

```
在编人数 = 实到人数（有则用）否则日历 headcount
一个人当天可用工时 = 日工时 ×（1 − 预留比例）
当天可用人·时 = 在编人数 × 一个人当天可用工时
```

预留比例沿用倒排已经在用的 `reserved_ratio`，不另设一个。演示配置里各组在编是 5，客户说的 4 按真实组填进日历，不把演示的 5 当成客户的数。

### 3.2 单人口径：人数按比例放大当天能做的版

一个人一小时做多少版，就是这条标准小时产能换算到版之后的值（BR-04）。这一单要的人·时 = 版数 ÷ 单人小时产能。计划人数只影响墙钟（几个人一起干，墙钟变短），不改变这一单消耗的人·时。

同一组、同一天：

```
已占用人·时 + 本单人·时 ≤ 当天可用人·时    才能再落
本单若单独占满这一天，版数上限 = 向下取整(当天可用人·时 × 单人小时产能)
```

在编从 4 改成 5，这一天的人·时和能做的版都按 5/4 增加。不同品项落在同一天时，各自按自己的单人小时产能扣人·时，扣的是同一个池子。

倒排循环里，单人口径的 `occupied` 从「已占版数」改为「已占人·时」。多人配合口径仍按版占用，两条不相加。

### 3.3 多人配合口径：在编不乘进产量

标准小时产能已经是「标定的这几个人一起干」一小时做多少版。组日版数上限仍是：

```
向下取整( 日工时 ×（1 − 预留比例）× 标准小时产能 )
```

在编写成 5 或写成 3，这个上限都不变。计划人数不等于标定人数时，仍只出 E8。

加人只有客户明确选的两种算法，系统不自动按比例猜：

| 客户的决定 | 产能怎么变 |
|------------|------------|
| 人数变了，重新标定标准小时产能 | 用新的产值重排。新产值由人填写，系统不按人数比例推 |
| 再开一整组 | 产能加上另一组同样的日产量。需要的人数是再一个标定人数，不是在编 +1 |

「4 人配合、再加 1 个人就多 25%」不成立，页面上不出现这个算法。

种子数据里已有多人配合、标定 4 人的品项（例如 S2 模具组、S5 手工组）。这些组如果只改日历在编、不改标定，产量保持原样，缺口里写明「产量未随人数变化」。

## 4. 排完之后给客户看的缺口

一轮倒排结束，按「部 × 组」出一张缺口。只统计这一轮放进排程的工单。待排订单不占日历，也不算进人·时缺口。

每一组四行：

| 行 | 含义 |
|----|------|
| 现有人数 | 这一组日历在编。窗口里各天在编不一样时，写出最小的那一天 |
| 需要人·时 | 已落下任务的人·时，加上未安置余量折成的人·时 |
| 现有人·时 | 从今天到这些单的交期里，每个工作日的可用人·时之和 |
| 要加的人数 | 见下面。0 表示按现有人数，这些单都能落在交期内 |

**单人口径的「要加的人数」取高峰日，不取窗口平均。** 窗口平均会把某一天不够的人摊平，显示加 1 人，当天其实要加 3 人。

```
某一天至少需要的人数 = 向上取整(这一天需要的人·时 ÷ 一个人当天可用工时)
要加的人数（估算）= 窗口内各天「至少需要的人数 − 当天在编」的最大值，小于 0 则记 0
```

未安置的余量还没有落到某一天。估算把它折成人·时后，按交期往前的工作日摊，只用于上面的高峰；这一行标明「估算」。

**准数用试排，不用估算代替。** 从现有在编起，每次加 1 人，在内存里用同一批工单再倒排，直到未安置清零且没有任务早于最早可排日，或试到在编 +30 仍做不到。要加的人数 = 第一次排通的在编 − 现有在编。试到顶仍做不到，写「加人仍做不到」，并沿用现有最快可完成日，不改交期。

**多人配合口径不跑「每次加 1 人」。** 缺口写：

- 标定人数、日历在编、两者是否一致
- 产量仍按标定，在编多出来或少了都不改版数上限
- 若客户要加产能：要么填写重新标定的产值再试排，要么选择再开一整组（人数步长 = 标定人数）

页面标题用客户的话：「这一组要加几个人」。旁边写出口径名称（单人 / 多人配合），避免两种算法看起来像同一个按钮。

## 5. 试加人数

计划在排程结果旁改一个组的试加人数（或直接改成目标在编），只影响这一次内存试排。

试排给出：

- 哪些原来未安置、或开工早于最早可排日的单，变得能在交期内做完
- 哪些单仍然来不及，以及现有的最快可完成日
- 试排用的在编、人·时、版数

丢弃则回到当前计划。采纳只把这个组的日历在编改成试排的人数，再由人触发一次正式倒排。采纳不改任何订单交期，不发布，不填写生产人员姓名。

单人口径：试加 1 人 = 该组每个工作日的可用人·时加上一个人的当天可用工时。  
多人配合口径：页面不提供「+1 人」；只提供「填写新的标准小时产能」或「再开一整组」。

## 6. 明确不做

- 安排张三某天做哪一单，或在「生产人员」里编造姓名
- 用 4 个人剩下的小时自动填上另一品（完整方案 §8，仍只评估）
- 多人配合口径按人数比例放大标准小时产能
- 因为算出要加人，就改组在编、改当前计划或改交期
- 把待排订单算进缺口，或为了算缺口给它们生成任务
- 有限产能求解、换模、遗传或线性规划
- 用实到人数去点名；实到只缩小当天可用人·时

## 8. 落地与测试

先写断言再改倒排。引擎仍是纯函数，`today` 由入参传入。

1. **单人、在编限制当天人·时。** 一组在编 4、日工时 8、预留 0、单人每小时 10 版。当天可用人·时 = 32，版数上限 = 320。在编改成 5，上限 = 400。同一天两个品项小时产能不同，占用的人·时相加，不把版数相加去对一个上限。
2. **多人配合不随在编变。** 标定 4 人、标准小时产能固定。在编写成 3 或 5，组日版数上限不变，并出 E8。禁止出现「5/4」这种产量。
3. **缺口取高峰。** 窗口里只有一天超出，要加的人数等于这一天的差，不等于各天差的平均。
4. **试排不写交期。** 在编 +N 的内存倒排能让一张原来未安置的单落在交期内；订单的 `due_date` 与当前计划任务都与试排前相同。试到上限仍做不到时，给出最快可完成日，计划不被硬排覆盖。
5. **未安置余量。** 估算行含未安置人·时，并标明估算；准数以试排为准。

改动的函数：`day_capacity` 的单人口径改为读组在编的人·时；倒排里单人口径的占用改为人·时；新增缺口与试加入参。`hours_wall` / `hours_man` / `group_rate` 的定义不改。新规则补进 `kb/coverage.yaml` 并挂卡之后，再改引擎投影。

验收时可以对着下面两句讲：

> 这一组日历上写几个人，单人口径就按这几个人算当天能做多少。人不够时，旁边写要加几个人；按这个人数试排一版，能看见哪些单变得交期内可做。交期要改仍然由人改。  
> 多人一起干、产量已经按这几个人标定过的组，改在编不改产量。要加人，要么重新标定一小时做多少，要么再开一整组。
