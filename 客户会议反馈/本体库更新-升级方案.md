# 本体库更新 · 升级方案

> 在交期锚种子已经跑通的前提下：先把存量全部按层挂上树，再规定每次开发变更必须同步改 `kb/`。不改倒排引擎，不自动升格「已封印」。

并行文档：[`封印本体知识库与三角色-升级方案.md`](封印本体知识库与三角色-升级方案.md)。

## 1. 目标

两件事：

1. **初始化收矿**：仓库里已有的规格、模型、角色、配置、测试，按主题链全部本体化（不是每层永远一张卡）。
2. **变更双胞胎**：之后每次功能/规则变更，代码和 `kb/` 走同一条 Ticket、同一次提交。
3. **无遗漏**：用闭集台账 + 测试对账，证明资产都挂上了卡；不是凭感觉。

失败形态：把 BR-01～50 整表贴进主张层；或改完 `engine/` 半年不改树。

## 2. 原则

- 行业对象与运营主张分开；BR 多数进**节点 / 投影**，只有价值句进主张。
- 新卡一律「假设」，人改「已封印」后才可当 `prove` 前提。
- 卡片中文栏、说明在最底下。运营用「命题」，行业对象用「定义」。边只写编号：撑住 / 细化 / 绑定 / 击败 / 禁止。
- 行业对象：独立事物可单独成名。若 B 是 A 的特征、槽或一次运行的结果，名称必须写成「A 的 B」，并填「属于: A」；禁止只留下 B（例如不要「计划差异」，要「倒排计划版本的工单差异」）。卡片平铺，父卡用「其下」列出直接孩子，加载器按「属于」反查对账。运营「绑哪个对象」仍指最小槽，不把运营卡嵌进对象树。
- 解析员只写 `kb/`；工匠不发明槽；禁止写回 `so_order.due_date`。
- Hook / CI 只检查，不改封印状态。

## 3. 初始化：按链收存量

现状：交期锚一条链已封印；版 / 组 / SPH / 工单只有对象名。下面按批补全，每批都要有对象槽 + 运营卡 + 论证键 + 投影文件。

| 批次 | 主题 | 主要出处 | 收成（示例，不是把 BR 当 L1） |
|------|------|----------|--------------------------------|
| 0 | 交期锚 | 已完成 | 订单.约定日 → 销售持有 → 变更审批 → 不得写回 |
| A | 计量与换算 | 规格 §3/§4、`models.py` `uom.py` | 版/枚/盒槽；换算走表（BR-01/03）在节点 |
| B | SPH 与两个小时 | `models.py` `capacity.py` | SPH 四元组；CREW 不再乘；墙钟 vs 人·时 |
| C | 成品 / 半成品 | `expand.py` `backward.py` | 先成品后半成品；成品变则重建半成品（BR-34） |
| D | 倒排与插单 | 规格 §6、`insert.py` `schedule.yaml` | 五幕、DUE_DESC / PIN_FIRST、栅栏与涟漪、死区 |
| E | 冲突与可承诺 | `conflicts.py` | E1–E10 软约束；不可行给最快日（BR-47/50） |
| F | 权责与模块 | `auth.py`、POC 范围、菜单 | 九个演示角色；M0–M9 节点；标「演示数据」 |
| G | 投影对账 | `packages/engine/*.py`、`tests/` | 每个引擎模块一条投影：已做到 / 未实现 / 漂移 |

批次内顺序：解析员出假设 → 你按链点头封印 → 补 `arguments.yaml` → `pytest tests/test_kb_*.py` 为该链加一条 `explain`。

顾问开放闲问的门槛：A–E 的核心对象与红线均已封印，且至少三条链可 `explain`（交期、版、CREW）。未达标只许继续收矿。

禁止：冷链、机台 APS、规格里没有的工序树。规格与代码不一致（如组码 SEMI）只记「漂移」投影，不顺手改引擎。

## 3.1 如何证明没有遗漏（覆盖对账）

「感觉收得差不多了」不算完成。**先固定资产清单，再要求每条清单都指向至少一张 `kb` 卡。** 清单是闭集：只扫约定目录，不靠模型回忆。

### 资产从哪来（闭集）

| 资产类 | 扫描哪里 | 一条资产是什么 |
|--------|----------|----------------|
| 业务规则 | 规格 §4 表格 | `BR-01` … `BR-50`（含 32b、39b） |
| 冲突码 | 规格 §6.5、`conflicts.py` | `E1` … `E10` |
| 行业对象 | `packages/engine/models.py` 的 class / Enum | `Order`、`Wo`、`Sph`、`Uom`… |
| 引擎模块 | `packages/engine/*.py`（除 `__init__`） | 每个 `.py` 一条 |
| 可调参数 | `config/*.yaml` 的键 | `fence_days`、`ripple_limit`、`deadband`… |
| 演示权责 | `auth.py` 的 `RoleCode`、`MENU.key` | `PMC`、`schedule`… |
| 产品模块 | POC 范围 M0–M9 | `M8` 排程… |
| 红线切片 | `.cursorrules` 业务红线条目 | 与 BR 对齐，可合并计 |
| 锁链测试 | `tests/test_*br*`、`test_db_redline.py` 等 | 每个测试文件一条投影 |

**不算必须本体化（刻意不收，但要登记理由）：** `seed/` 演示数字、`web/vite.config.ts`、主题、Workbuddy 讲稿、`.venv`。讲稿可以绑到已有节点的「对外怎么说」，不另开对象。

### 覆盖台账

台账在 [`kb/coverage.yaml`](../kb/coverage.yaml)。每一行：

```yaml
- 资产: BR-27
  类: 业务规则
  出处: 斯芬克斯-排程服务POC-开发需求规格.md
  挂到: [F.l3.due_change_via_approval, F.l4.br27_no_write_due]
  状态: 已封印          # 已封印 | 假设 | 刻意不收
  理由:                  # 仅「刻意不收」必填
```

规则：

- 同一资产可挂多张卡（主张 + 节点 + 投影），但**不能零挂**，除非「刻意不收」。
- BR 挂到节点/投影即可，不必每条 BR 一张主张。
- `models.py` 里每个业务 class 至少挂一个行业对象或槽。
- 每个 `engine/*.py` 至少出现在一张投影的「落在哪个文件」。

初始化收矿时，解析员每做完一批，先跑对账：清单有、卡没有 → 缺口；卡有、清单没有 → 多收或幻觉，要补出处或删卡。

### 机器怎么咬住（`tests/test_kb_coverage.py` / `tests/test_kb_binds.py`）

对账必须能红，不能只靠读方案：

1. **解析规格**，抽出全部 `BR-xx` / `E×`，与台账比对，缺行即失败。
2. **枚举** `packages/engine/*.py`、`config/*.yaml`，未入台账或未挂卡即失败。
3. **解析** `models.py` 的 `class`，未挂对象/槽即失败。
4. **解析** `RoleCode` 与 `MENU.key`，未入 F 批权责卡即失败。
5. 台账「挂到」的编号必须在 `kb` 里存在；标「已封印」则卡状态也必须是已封印。
6. 「刻意不收」必须有「理由」，且不得用于 `engine/*.py` 与 `BR-*`（这两类禁止逃课）。

初始化完成的**唯一数字标准**：台账覆盖率 100%，且禁止逃课的两类没有「刻意不收」。A–G 做完只是过程；对账全绿才叫没有遗漏。

存量对账是一次性大扫；之后不靠每周全量重扫，而靠第 5 节：新文件、新 BR、新模型进仓库时，台账测试会先红，逼你补卡。

## 4. 之后每次开发：同一条变更

```text
需求 / 会议
  → 顾问：对象槽在不在、落在哪一层、撞哪条禁止
  → Ticket（四项缺一不可）
  → 工匠改代码 + 同提交改 kb/
  → 功能测试 + test_kb_*
```

Ticket 四项：

1. **事实编号**（撑住的主张/节点）
2. **绑哪个对象**（已封印的槽）
3. **禁止**（至少抄 BR-27 或本节点禁止）
4. **文件列表**（代码 + 将改的 `kb/*.yaml`）

谁改库：

| 变更性质 | 先谁 | `kb/` 怎么动 |
|----------|------|----------------|
| 只改文案、文件搬家 | 工匠 | 改投影「落在哪个文件」 |
| 新页面、对象已有 | 顾问确认槽 → 工匠 | 加 L4，必要时加节点「对外怎么说」 |
| 新主数据字段 / 新对象 | 解析员假设 → 你封印 → 工匠 | 先行业槽，再生表 |
| 谁能改什么变了 | 解析员 + 顾问 | 先权责/节点，再代码 |
| 卖法 / 承诺变了 | 顾问停工 | 先主张，禁止在倒排里发明 |
| 会议新说法、尚无代码 | 解析员 | 只出假设，不开工匠 |

`gate_ticket` 已拒绝：无绑定、写回约定日、改引擎/配置却未列出 `kb/` 文件。

## 5. 用仓库逼同步（待落地，比靠自觉强）

已落地：

1. **规则**（`.cursor/rules/kb-sealed.mdc`）改引擎或配置必须同步投影/台账。
2. **`tests/test_kb_binds.py`**、**`tests/test_kb_coverage.py`** 如上。
3. 本地以 `pytest -q tests/test_kb_*.py` 为准。不自动改 YAML。
4. **不做**：保存即写入、模型私自把假设改成已封印、全量重扫当日常默认。

新收的主题链除交期锚和「版 / CREW」红线外，状态仍是**假设**，等人按链点头封印后才可当更多 `prove` 前提。

## 6. 验收

**初始化完成：**

- `tests/test_kb_coverage.py` 全绿：BR、E 码、`models` 类、`engine/*.py`、配置键、角色与菜单均在台账且已挂卡。
- A–G 过程做完，且 `kb/` 不再是「每层一张」。
- `python -m kb explain` 能讲清：不改约定日、先归到版、CREW 不再乘。
- 漂移卡存在，引擎无顺手修改。

**单次开发完成：**

- 同一次提交里能看到代码 diff 与对应 `kb/` diff（除非 Ticket 写明纯修复且无新绑定）。
- 顾问记录了层与禁止项；工匠未写回约定日。

## 7. 本期不做

POC 知识库 GUI、Neo4j、LangGraph、客户远程改码。那些仍按三角色方案的二期 / 三期。
