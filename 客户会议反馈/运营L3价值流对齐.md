# 运营 L3：价值主张兑现为价值流

> 已采纳的结构（梁彬 + 顾问讨论）。实例只许用规格 / POC 已有事实。  
> 生成步骤与批次：[`运营本体生成-升级方案.md`](运营本体生成-升级方案.md)。  
> 并行：[`运营本体缺口-请Gemini评思路.md`](运营本体缺口-请Gemini评思路.md)、[`行业本体设计-请Gemini评合理性.md`](行业本体设计-请Gemini评合理性.md)。

## 1. 咬合关系（采纳）

$$
\text{L1 价值主张 (VP)}
\xrightarrow{\text{兑现}}
\text{L3 一条企业级价值流}
\xrightarrow{\text{阶段}}
\text{环节}
\xrightarrow{\text{使能}}
\text{支撑流程 / 许可协议}
$$

- 一张已封印 VP **至少**对应一条 L3 价值流。一张主张可以兑现多条流；一条流可以撑住多张主张。不是「一个主张配一条同名流程」机械对称。
- 价值流是 **VSM 容器**，不是 BPMN、不是菜单清单。
- 环节是主链上的一站（有阶段产出）。
- 支撑流程 / 许可是让这一站转得起来的协议（现有 `F.l3.*` 算核节点属于这一级）。
- 诊断：L1 异常 → 哪条价值流 → 哪个环节 → 哪条协议被击穿 → L4 文件。不先翻菜单。

卡片仍平铺。边用中文：价值流 `撑住谁` → L1；环节 `属于` 价值流；许可 `属于` 环节（或直接属于价值流，若暂不拆环节卡）。父卡 `其下` 与反查对账。不要引入 `realizes_value_proposition` / `VALUE_STREAM` 英文键。

`层` 取值（运营）：主张 | 权责 | **价值流** | **环节** | 节点（许可） | 投影。  
演示菜单、模块号、登录角色继续 L4，不进价值流主树。

## 2. 本厂只先铺一条流（能封印的 VP）

规格已够的 VP 合成一条来兑现（不要拆成两条并列的「新鲜度 VP」和「交期 VP」）：

**L1**（已有或可补，禁止写冷链原因）：

- `F.l1.due_is_shared_reality`：约定日是唯一对外锚  
- （待补假设/封印）按单、无成品仓交付装饰件  

**L3 价值流**（一张卡，假设起步）：`F.l3.vsm.order_to_delivery`  
名称：按单履约价值流  
撑住谁：上面两张 L1  
其下：四个环节  

| 环节 | 阶段产出 | 已有许可（挂其下） | 状态 |
|------|----------|-------------------|------|
| 需求与约定确认 | 约定日进系统，数量能说到版 | `F.l3.due_change_via_approval`、`F.l3.normalize_to_board` | 许可已封印 |
| 倒排与齐套锁定 | 贴约定日的计划，半成品有着落 | `F.l3.backward_place`、`F.l3.finished_then_semi`、`F.l3.kitting`、`F.l3.fence_ripple`、`F.l3.sph_and_hours` | 多为假设 |
| 双部制成与报工 | 工单落到组日，欠产回池 | 报工考勤上限、未完回池（POC 已有故事，**尚无独立许可卡**，先占位假设） | 缺口 |
| 履约关闭 | 给最快日或交付，不改锚 | `F.l3.soft_conflicts` | 出货/回款规格不足则**不建协议卡** |

L2 只在环节上写「谁有权」指向能力卡（销售承诺、计划排产、一部/二部制成），组织全称未确认则假设。

## 3. 明确不收（Gemini 文里有、库里禁）

「大客户打样孵化价值流」以及下列协议：**在对应主张未向客户对齐、未写入 L1 之前不建树**。有主张之后可以另开价值流。

禁止写进价值流（即使标假设也先不要，除非纪要出现）：

- 冷链熟化领料、温控装箱、成品冷库、温控车辆  
- 连锁茶饮/烘焙巨头分群、展会打单、商票 45 天、试机进场  
- 二部「原料组 / 生巧组 / 半成品组」、双部六组（代码是三组码 + 部门）  
- 非标设备采购作为排产硬约束、机台 APS  

打样闭环、合同回款若只用 POC 页面当出处：可各做**支撑流程假设卡**，挂在「需求」或「履约关闭」下，不得升成第二条已封印 VP。

## 4. 门禁

1. 每张已封印 L1 必须能指出 ≥1 张价值流卡（可假设）。  
2. 价值流每个环节：要么 `其下` 有许可/支撑，要么说明写「缺口、顾问停」。  
3. 新许可节点必须 `属于` 某个环节或价值流，禁止再平铺进 L3 根。  
4. 软件闭集（BR / engine）仍扫；运营闭集扫「已点名的价值流 × 环节」，不扫 SCOR 五段、不扫 MENU。
