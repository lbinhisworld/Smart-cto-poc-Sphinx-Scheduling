## 三、算法说明（客户能懂版 + 给设计师的分镜）

### 3.1 核心思想（一张图）

```mermaid
flowchart LR
  A[销售订单<br/>数量·交期] --> B[展开成品工单<br/>换算到「版」]
  B --> C[按规则排序<br/>默认交期晚的先占格]
  C --> D[倒排落位<br/>从交期往前填]
  D --> E[展开半成品<br/>库存抵扣后补工单]
  E --> F[再倒排半成品]
  F --> G[冲突体检 E1~E10<br/>红/黄/灰/蓝]
  G --> H[人：试排·拖拽·沙箱<br/>确认后发布]
```

**旁白**：  
「我们不是替您拍板交期，而是从您定的交期**往回推**，看产能和齐套能不能接上。接不上就**亮灯**并算出**物理上最快哪天能交**，交给计划和销售决定要不要改交期、加班或调库存。」

### 3.2 七步流水线（与系统一致）

| 步骤 | 名称 | 客户听得懂的说法 | 画面建议 |
|:---:|---|---|---|
| 0 | 需求展开 | 把「200 盒」换成内部统一的「版」 | 盒→版换算动画，向上取整 |
| 1 | 工时与组日产能 | 每组每天能排多少版（扣 15% 预留） | 日历格 + 底部产能条 |
| 2 | **倒排落位** | 从交期那天往前，一天一天塞任务 | 光标从右向左移动填块 |
| 3 | 半成品展开 | 成品开工日定下来后，反推半成品要哪天交 | 箭头：二部 → 模具，提前 4 天 |
| 4 | 再倒排半成品 | 二部也按同样规则往前填 | 二部行填块 |
| 5 | 冲突检测 | 装不下、超产能、包材未到…分级提示 | 右侧冲突面板 |
| 6 | 人确认 | 试排、拖拽、插单对比，**不改订单交期字段** | 发布按钮 + diff 弹窗 |

### 3.3 三条业务红线（脚注常驻）

1. **交期是锚**：系统**不会**自动写回改客户交期（只能人改）。  
2. **先成品后半成品**：成品计划一动，半成品工单**重建**再排。  
3. **默认排序是「交期晚的先排」**（`DUE_DESC`）：这样加单/加量时，其他单在倒排世界里表现为**往前挤**，而不是把晚交期单拆到很远的碎空位；**插单时**才切换「变更单先占位」（`PIN_FIRST`）。

### 3.4 冲突四色（右侧面板语义）

| 色 | 代表 | 典型码 | 客户动作 |
|---|---|---|---|
| 红 | 物理窗口不够 / 半成品赶不上 | E1、E2 | 看「最快可完成日」，再决定是否找销售改交期 |
| 黄 | 能排但有风险 | E3 包材、E4 组日超限、E9/E10 齐套 | 加班、顺延、协调包材 |
| 灰 | 数据未校准 | E5 SPH 低置信 | 参考排，尽快校准参数 |
| 蓝 | 可合并共线等优化提示 | E7 等 | 可选合并省换线 |

## 四、算例脚本 A —— 手工单（最简单，建立信任）

**订单**：SO-001 · 品项 P1 · 520 盒 · 交期 **2026-10-08**  
**假设 today**：**2026-09-15**（演示固定「今天」）  
**工艺**：仅 **手工组**，无半成品。

### 分镜脚本

| 镜号 | 画面 | 旁白 |
|:---:|---|---|
| A1 | 订单卡飞入 | 「蓝岛烘焙要 520 盒插件 P1，交期 10 月 8 日。」 |
| A2 | 换算：盒→版（含损耗，向上取整） | 「系统内部只算『版』，避免销售和车间各说各话。」 |
| A3 | 矩阵：手工组一行，从 10/8 往前填 | 「从交期往回一天一天填，工作日才填，休息日跳过。」 |
| A4 | 产能条 <100% 绿色 | 「每天填多少，看这组当天还剩多少产能。」 |
| A5 | 无红灯，「可试排发布」 | 「能排下就不改交期，计划员确认后发布到车间。」 |

**Designer 备注**：此例不需要二部行、不需要依赖箭头。

## 五、算例脚本 B —— 模具 + 半成品（核心卖点，建议占时长 40%）

**订单**：SO-002 · 童乐坊 · 品项 **P2 造型糖花** · **200 盒** · 交期 **2026-10-07**  
**包材就绪**：ready_date **2026-09-15**  
**today**：**2026-09-15**  
**库存**：半成品 **S2 现有 130 版**（演示可展示占库后**净需求 282 版**）  
**路线**：成品 **模具组**；半成品 **S2 → 二部半成品组**；成品开工前 **4 天** 半成品须就绪（lead time）。

### 正常场景（种子默认交期 10/7）— 分镜

| 镜号 | 画面 | 旁白 |
|:---:|---|---|
| B1 | 两道工序竖向：二部 → 模具 | 「P2 要先做胚（二部），再到模具组成型。」 |
| B2 | 先排成品：模具组从 10/7 往前，约 **1236 版** 分摊多日 | 「先假设模具能在交期前做完，倒排出成品每天做多少版。」 |
| B3 | 成品最早开工日出现（示意 **9/18** 一带） | 「成品最早哪天开工，倒推半成品最晚哪天要交。」 |
| B4 | 算半成品：毛需求 − 库存 130 = **净 282 版** | 「库存能覆盖一部分，剩下的才开半成品工单。」 |
| B5 | 二部行：在 **9/25 前后** 集中 **282 版**（与种子说明一致） | 「二部在成品开工前 4 天窗口内把 282 版排进去。」 |
| B6 | 箭头：S2 块 → P2 块，标注 FS+4 天 | 「依赖是硬逻辑：胚不到，成品不能开工。」 |
| B7 | 冲突面板 0 红或仅黄 | 「交期够用时，计划员看到的是可执行的日程，而不是系统擅自改交期。」 |

**屏幕字卡（数字）**：

```
SO-002 · P2 · 200 盒 → 约 1236 版（成品）
S2 毛需求 − 库存 130 → 工单 282 版（二部）
交期锚点：2026-10-07（不变）
```

### 冲突场景（会议常演示）— 交期改早

**操作**：同一 SO-002，交期改为 **2026-09-23**（仍 today=9/15）。

| 镜号 | 画面 | 旁白 |
|:---:|---|---|
| B8 | 倒排光标卡在 earliest（今天/齐套日）前，剩余版数 >0 | 「往前推已经推到『最早能开工』那天，还有版数塞不下 —— 这叫**未安置**。」 |
| B9 | 冲突面板 **E2 红**：半成品来不及 | 「红灯不是说销售错了，而是**倒排窗口**里二部来不及在成品开工前补齐。」 |
| B10 | 建议区：**最快可完成日 约 9/29**（示例口径，与 POC 一致） | 「系统算物理最快哪天能交，**建议销售协商**；交期字段仍由人改，系统不偷偷改。」 |
| B11 | 若最快日 **不晚于** 客户交期 | 「有时红灯是『贴交期往回填太紧』，**交期本身够**，不要误导销售去改交期 —— 应加班/加人/调序。」 |

**屏幕字卡**：

```
客户要：9/23
物理最快：约 9/29（示例）
结论：需协商或调整产能/库存 —— 系统只给事实，不替销售承诺
```

## 六、算例脚本 C —— 插单与涟漪（纠正「被挤订单延后」误解）

**角色**：  
- 池内已有若干单（示意 SO-001~003）  
- **插单** SO-004 · P2 · 紧急 · 交期近  

### 分镜

| 镜号 | 画面 | 旁白 |
|:---:|---|---|
| C1 | 排序切换动画：`DUE_DESC` → `PIN_FIRST` | 「平时晚交期先占格；**插单/改单**时，让这一单先占位。」 |
| C2 | 新单块插入矩阵 | 「插单不是 magic，是重新跑同一套倒排规则。」 |
| C3 | 其他订单任务块**整体左移（日期提前）** | 「在倒排模型里，挤占表现为别的单**开工提前**，不是把别人一律往后推。」 |
| C4 | diff 弹窗：移动 N 单、超交期 M 单 | 「点发布前，必须看见代价 —— 这是 POC 最该打磨的一屏。」 |
| C5 | 时间栅栏示意：today ~ today+4 冻结 | 「近 4 天冻结区内的变动要人工确认，避免现场被打乱。」 |

**禁止旁白**：「插单会把所有订单交期顺延。」  
**正确旁白**：「可能提前、可能装不下（E1），要看最早可排日和产能。」

## 九、旁白全集（可整段 TTS）

**开场**  
「斯芬克斯排程服务，帮助计划和销售回答三个问题：哪天必须开工、二部胚来不来得及、交期在物理上是否可行。做法是 JIT 倒排：从客户交期往回填，而不是从今天往后猜。」

**倒排**  
「每一天能排多少版，取决于这组的标准产能、出勤日历，以及当天已经被其他订单占用的格子。填满了就继续往前一天，直到全部版数安置完，或者推到最早可开工日仍有余量 —— 后者就是未安置，系统用 E1 或 E2 红灯提示。」

**半成品**  
「必须先排成品，再算半成品要多少、何时必须交。库存能抵扣的不再生产。成品开工日减去提前期，就是半成品的交期锚点。」

**冲突**  
「红色必须让人看见，但不会阻断试排；是否改交期、是否加班，由人和销售决定。系统可以算最快可完成日，但不会自动改订单上的交期。」

**收尾**  
「这就是 POC：规则透明、可试排、可对比、可撤销。正式上线后，参数来自您的品项、SPH 和组日历，逻辑与演示一致。」
