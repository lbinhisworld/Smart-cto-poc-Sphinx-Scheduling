# 行业本体提取 · 升级方案

> 替代「从 `models.py` 扫 class 就当行业对象」。  
> 评稿：[`行业本体设计-请Gemini评合理性.md`](行业本体设计-请Gemini评合理性.md)。  
> 运营如何生成：[`运营本体生成-升级方案.md`](运营本体生成-升级方案.md)。  
> 软件闭集与变更双胞胎：[`本体库更新-升级方案.md`](本体库更新-升级方案.md)。  
> 不改 `packages/engine/`，不自动封印，禁止写回约定日，禁止补冷链 / 机台 APS / 规格没有的工序树。

## 1. 目标

生成出来的行业库必须能回答两句，且两句分开：

1. **巧克力装饰件按单排产里有哪些格子、量纲和缩写**（离开斯芬克斯编制仍能被指认）。  
2. **这一趟倒排引擎留下了哪些运行结果**（计划版本、冲突条、五幕回放）。

不再把「引擎有一个 class」当成「行业有一个对象」。

失败形态：再扫一轮 `models.py` 把 `TraceAct`、`DiffEntry` 做成行业根；或借「行业通用」补客户分群、渠道、冷链仓、完整工艺路线；或拆掉 `属于` 构成树改成英文 OWL 网。

## 2. 两轴三林（生成时必须遵守）

```text
运营（谁 / 依据什么主张 / 怎么做）
  L1 主张 → L2 能力/权责 → L3 价值流 → 环节 → 许可
        │ 绑最小槽
        ▼
行业主林（有什么东西、什么量纲）
  销售订单 / 品项 / 版 / 单位 / 组 / 工单 / 组日任务 / SPH
        │ 一次运行才出现
        ▼
运行结果林（这趟算核的信封与切片）
  一次倒排 I/O、齐套快照、冲突、插单、计划版本、差异、五幕、可行性
```

| 林 | 套 | 层 | 收什么 | 不收 |
|----|----|----|--------|------|
| 行业主林 | 行业 | 对象 / 槽 | 能离开本厂编制被指认、倒排必须用到的名词与量纲 | 一部/二部编制名、审批权、BR 乘法、菜单 |
| 运行结果林 | 行业 | 运行结果 | 一次倒排或插单才有的信封、快照、标记、回放 | 品项主数据、组编制、销售约定 |
| 运营 | 运营 | 主张…投影 | 谁有权、走哪条流、代码落在哪 | 不要再把 SPH/墙钟做成运营对象 |

判据（替代「食品工业词典里有没有」）：

> 离开斯芬克斯的组织编制和审批权，这件东西是否仍能被指认，并且倒排或工时必须用到它。

按这个尺子：手工组 / 模具组 / 浇注组留主林（制成工作中心）。「一部 / 二部」这个名字归运营 L2（已有 `F.l2.cap_dept1` / `cap_dept2`）。成品工单 / 半成品工单用「是一种」，不靠部门对象冒充分类。

五幕回放、`ScheduleInput` 进运行结果林，不进主林。计划版本、软冲突、插单：离散制造说得通，但**形状是引擎信封**，也进运行结果林；顾问讲「一张单怎么变成组日任务」不走这林。

## 3. 边的种类（只中文）

构成树继续是顾问 `tree` / harvest 的唯一从上到下路径。网状事实用**第二类边**，不替换第一类。

| 边 | 栏名 | 何时用 | 进不进 `其下` | 本厂例 |
|----|------|--------|---------------|--------|
| 构成 | `属于` | B 不能离开 A 被指认（槽、一次结果、真特征） | 进。父卡 `其下` = 加载器按 `属于` 反查 | 约定日属于订单；组日任务属于工单 |
| 关联 | `关联` | 两端都能独立存在；可多端 | **不进** `其下` | 工单来自订单；工单用品项；任务落在组；SPH → 品项 × 组 |
| 分类 | `是一种` | 子类，不是父的槽 | 不进 `其下` | 成品工单是一种工单；半成品工单是一种工单 |

命名：

- 有 `属于` ⇒ 名称必须能读出父对象（继续「A 的 B」，或明确含父称呼）。  
- 有 `关联`、无 `属于` ⇒ **不要**为了过门禁硬造「一次倒排的输入输出」这种假从属名。独立名单只收：无 `属于` 的主林根 + 运行结果林的根。  
- 禁止只提取中性词（不要「计划差异」，要「倒排计划版本的工单差异」——这条仍适用于运行结果林内部构成）。

槽编号仍是 `父编号.后缀`。运营 `绑哪个对象` 仍指**最小槽**，不绑父对象冒充。

`prove` / `explain` 第一期仍只沿：撑住 / 属于 / 绑定。`关联` / `是一种` 给 `tree`、`ask` 对词和顾问指路，不自动当证明前提。

## 4. 量纲与缩写（主林必收）

规格 §3 术语表里的**量纲行**是行业出处，不是运营口号。

### 4.1 SPH

升成独立对象，**取消** `属于 D.item`。

- 名称：品项在组上的标准小时产能  
- `别名`：`SPH` / `Standard Pieces per Hour` / `sph`  
- `关联`：`[D.item, D.group]`  
- 定义只写：某品项在某组上的四元组（值、口径、标定人数、单位）。  
- **不要**把「CREW 禁止再乘人数」写进定义或 `对外怎么说`——那句留给 `F.l3.sph_and_hours` / `F.l1.crew_in_sph`。

子槽（皆假设起步，编号镜像父）：

| 编号 | 名称 | 别名 |
|------|------|------|
| D.sph.value | SPH 的值 | `sph_value` |
| D.sph.basis | SPH 的口径 | `sph_basis` / `SINGLE` / `CREW` |
| D.sph.crew | SPH 的标定人数 | `sph_crew` |
| D.sph.uom | SPH 的单位 | `sph_uom` |

口径槽的定义可以说「`CREW` = 一组配合一小时，人数已含在值内」——这是量的定义。运算禁令仍在运营许可。

### 4.2 两个小时

挂在 `D.wo_task` 下，与约定日挂在订单下同一纪律。禁止只写在任务卡散文里。

| 编号 | 名称 | 别名 | 定义要点 |
|------|------|------|----------|
| D.wo_task.hours_wall | 组日任务的墙钟工时 | `hours_wall` / 墙钟 | 占日历的小时，排日程、看组日负荷 |
| D.wo_task.hours_man | 组日任务的人·时 | `hours_man` / 人·时 | 墙钟 × 投入人数，算成本 |

定义可写量纲关系「人·时按墙钟乘投入人数」。禁止混用去排产/计价 → `F.l3.sph_and_hours`，并改绑三个叶子：`D.sph` + 两个小时槽。

组速 `group_rate`（版/小时）、日容量 `day_cap`（版）：**可以后补**，不与两个小时同一批先封。

### 4.3 别名栏

对象、槽、**运营能力卡**都加 `别名`（字符串列表）。`ask` / 顾问「什么是 X」先对 `别名` 再对 `名称`，**跨两套检索**，不要因为 PMC 不在主林就答「库里没有」。  
`对外怎么说` 给人听的一句；`别名` 给对词。不要另开「缩写本体」。

制造业通用词**必须能被问到**，但不都做成行业对象。先判它是格子、量纲、一次运行结果，还是职能/方法：

| 词 | 展开 | 进哪 | 挂哪张卡 | 不要做成 |
|----|------|------|----------|----------|
| BOM | Bill of Materials / 物料清单 | **主林** | 已有 `D.bom`。补别名；名称可保留「成品装饰件的子件」，对外先说物料清单 | 不要只当菜单「BOM 工艺」或 `bom.py` 投影 |
| WO | Work Order / 工单 | 主林 | `D.wo` | |
| UoM | Unit of Measure / 计量单位 | 主林 | `D.uom` | 不要收成通用 SI 单位库 |
| SPH / 墙钟 / 人·时 | 见 §4.1–4.2 | 主林 | `D.sph`、两个小时槽 | |
| 工艺路线 | Routing / ItemRoute | 主林 | `D.item_route`。只收「要不要半成品、提前几天」 | 不要升完整工序树 |
| 提前期 | Lead Time | 主林槽 | `D.item_route` 下补槽（可后补） | |
| 齐套 | Kitting | 运行结果林 | `D.kit`（本趟占库快照）。别名可含「齐套」 | 不要当成金蝶即时库存主档 |
| PMC | Production & Material Control / 生管 | **运营 L2** | `F.l2.cap_plan` 加别名 `PMC` / `生管`。登录号仍是 `F.l2.role_PMC`（演示投影） | **不要**开 `D.pmc` 行业对象。换一家厂可能叫计划课 / 生管，编制不是行业定律 |
| MTO | Make to Order / 按单生产 | 运营 L1 | `F.l1.mto_no_fg_stock` | 不要做成品项分类 |
| JIT | Just in Time | 运营许可 | `F.l3.backward_place` | 不要当主林对象 |
| 时间栅栏 / 冻结区 / 涟漪 / 死区 / what-if | 排程方法 | 运营许可 | `F.l3.fence_ripple` 等 | 同上 |
| 一部 / 二部 | 本厂编制 | 运营 L2 | `F.l2.cap_dept1` / `cap_dept2` | 不要当主林根 |
| BR-xx / E1–E10 | 规则与冲突编号 | 覆盖台账 | 已有挂点 | 不当对象 |

规格和 POC **没有**、禁止借「制造业通用」补进来的：ERP、MES、APS、SOP、SKU 分群、WIP 仓、FIFO、MRP 运算、完整工艺路线树、客户分群、渠道。这些词客户问到就说「本期不收」，不建卡。

`D.bom` 已在树上却几乎问不到「BOM」，是因为名称写成引擎口吻、没有别名。补别名即可，不必再扫出一个新对象。  
`ask "PMC"` 应落到计划能力，并说明「这是本厂生管职能的通用叫法，不是行业物理对象」；禁止落到演示菜单或 SSO。

## 5. 槽闭集（相对现模型，生成时按列收）

### 5.1 销售订单 `Order`

| 必须先收成槽 | 可以后补 | 不要收 |
|--------------|----------|--------|
| 约定日 `D.order.due_date`（已有） | 要货日 `ready_date` | 金额（排序权重） |
| 数量 `D.order.qty` | 紧急 `is_urgent` | 客户等级（权重配置） |
| 单位 `D.order.unit` | 销售员名 | 客户分群、渠道 |
| 品项：用 `关联` 指向 `D.item`，不要做成订单的构成孩子 | 客户名 | 规格没有的字段 |

`F.l1.mto_no_fg_stock` 现在绑 `D.order` 整卡，本方案落地后改绑叶子（数量或约定日），或说明它绑的是「按单交付」这件事而不是某个字段——禁止继续用父对象冒充槽。

### 5.2 工单 / 任务

必须有：工单 ←`关联`→ 订单、工单 ←`关联`→ 品项、组日任务 ←`关联`→ 组、两个小时槽。  
成品 / 半成品：两张分类卡 `是一种 D.wo`，不要靠 `D.dept` 冒充。

### 5.3 对象卡能不能写规则

定义栏只回答「它是什么、量纲是什么」。  
`D.board` 现定义「枚和盒必须先换成版再算工时」、`D.wo` 现定义「先排成品再排半成品」：运算句下沉到已有许可 `F.l3.normalize_to_board` / `F.l3.finished_then_semi`。对象卡改回点名尺子或工单本身。

### 5.4 不要抬抽象父（货物规格 / 主数据 / 资源）

截图里版、组、品项、订单平铺，看起来「缺一层」。**不要**为此新建 `货物规格`、`主数据`、`生产资源` 当构成父。那是展示文件夹，不是独立事物。

| 现根 | 它是什么 | 若抬「货物规格」会怎样 |
|------|----------|------------------------|
| 版 | 内部唯一**尺子**（量纲）。枚/盒先换成它 | 版不是某批货的规格。规格里的是「这品项一盒几版」 |
| 组 | **工作中心**（手工/模具/浇注）。日历、任务落在它上面 | 组不是货物属性。品项「走哪条组」是关联，不是组属于规格 |
| 装饰件品项 | 可排产的主数据：销售单位、版盒比、损耗、颜色、默认组 | **这张就是货物规格**。补别名即可，不新开父卡 |

货物规格上真正的槽（可后补，不要一次收完 `Item` 全字段）：

- 必须有：默认组（`关联` 到 `D.group`，不是构成孩子）、销售单位  
- 可以后补：版盒比 `board_per_box`、枚版比 `pcs_per_board`、损耗、颜色  
- 不要收：`computable` 等引擎开关

`/kb` 若要好看，用**展示分组**（计量 / 工作中心 / 品项主数据 / 单据），分组名不进 `kb/`、不写 `属于`。顾问绑槽仍绑 `D.board`、`D.group`、`D.item.…`，禁止绑「货物规格」冒充叶子。

版与 `D.uom`：版是计量枚举里的特权取值，可用 `是一种` 指向计量单位；**不要**改成 `属于 D.uom`（版能单独被指认，已封印编号不改）。

## 6. 生成顺序（切断「先有 class 再有行业卡」）

```text
1. 人写「装饰件排产最小对象清单」（假设，见 §8.1）
2. 规格 §3 量纲行 → 主林对象/槽 + 别名
3. 槽不够时先补主林叶子，再让运营改绑
4. models.py 每个 class / 关键字段只能挂到：
      主林叶子  或  运行结果林  或  L4 投影
5. 运行切片（Trace* / Diff* / ScheduleInput）禁止再挂主林根
6. 人点头后才把主林清单上的叶子升封印；运行结果林可长期假设
```

解析员：只写 `kb/`。先交「这张卡进哪一林、哪条边、绑给哪条运营许可」再写卡。  
顾问：主林未封或槽没有 → 缺前提，停止。运行结果林未封不阻断「一张单怎么变成任务」。  
工匠：Ticket 仍绑**已认可链上的最小槽**；禁止发明格子。

覆盖门禁改判：

- 旧：每个 `models` class 必须挂一张「行业对象」。  
- 新：每个 class **必须挂到某张卡**，但卡可以是运行结果或 L4；`ScheduleInput` / `TraceAct` 不得再要求对应主林对象。

## 7. 提取规则（解析员清单）

遇到一段纪要、一个 class 或一个字段时，按序问，答不上就停：

1. 这是**格子/量纲**、**一次运行的结果**，还是**谁有权/怎么走**？  
   格子/量纲 → 主林。运行结果 → 运行结果林。权责/流程/BR 乘法 → 运营。页面 → L4。  
2. 离开本厂编制还能指认吗？不能（一部、销售中心、PMC 登录）→ 不进主林。  
3. 规格 §3 / 模型字段有没有这个名字？没有 → 不建卡（冷链、客户分群、完整工序树）。  
4. B 能否离开 A 存在？不能 → `属于` +「A 的 B」。能 → 独立对象或 `关联` / `是一种`。  
5. 它是缩写吗？写入已有卡的 `别名`，不新开缩写卡。  
6. 运营要绑它吗？必须落到叶子槽。没有槽 → 先假设槽，或顾问停。  
7. 新卡状态=假设。已封印卡改边、改林、清定义里的 BR 动词时，**先假设新形状给人看**，不偷偷改已封印命题。

禁止：

- 冷链、温控仓、机台 APS、原料组/生巧组、客户分群、渠道、完整工艺路线。  
- 把 BR-01～50 写进对象定义。  
- 为对称给每个 `models` 字段建槽（金额、客户等级不要收）。  
- 用 IS_A / REFERENCES / OWL 当 YAML 栏名。  
- 拆掉 `属于` 构成树。  
- 为了独立名单去给运行信封起带「的」的假从属名。  
- 为了树好看抬抽象父：`货物规格`、`主数据`、`生产资源`、`行业概念`。品项已是规格；版是尺子；组是工作中心。

| D.sph | 取消 `属于 D.item`；加 `关联` 与四元组子槽、别名；定义去掉 CREW 禁令 |

| D.wo_task | 留主林。补两个小时槽、`关联` 到组 |
| D.wo_dep / D.unplaced / D.coline | 主林构成可留（依赖、未放下、并线是工单/任务上的事实）。并线若更像本趟标记，可改挂运行结果林——第一批先留主林，说明写「排程标记」 |
| D.dept | **降出主林独立根**。编制名并入运营 L2；主林改用成品/半成品「是一种」。`F.l2.cap_dept1/2` 改绑工单分类或组，不绑这张企业编制卡 |
| D.schedule_io 及其下 kit / conflict / insert / plan_version / diff / trace | **整枝改层为运行结果**。名称可去假「的」。coverage 改挂这里或 L4 |
| D.feasibility | 运行结果林；可 `关联` 订单，不要假装是订单的构成槽 |

## 8.1 主林最小清单（人写、假设）

顾问要讲清「一张单变成组日任务」而不编字段，主林至少这些（封印另一步）：

1. 销售订单 + 约定日 + 数量 + 单位  
2. 装饰件品项（关联，不是订单孩子）  
3. 版  
4. 装饰件计量单位 + 品项换算  
5. 组  
6. SPH + 四元组槽 + 双端关联  
7. 工单 + 是一种（成品/半成品）+ 关联到订单/品项  
8. 工单的组日任务 + 墙钟 + 人·时 + 关联到组

## 11. 怎么测、怎么用

```bash
pytest -q tests/test_kb_*.py
python -m kb tree
python -m kb ask "什么是 SPH" --角色 销售
python -m kb ask "什么是 BOM" --角色 计划
python -m kb ask "PMC 是什么" --角色 销售
python -m kb ask "墙钟和人时有什么区别" --角色 计划
python -m kb explain C.crew_no_extra_multiply --情境 按单 --角色 计划
python -m kb harvest-check D.wo_task.hours_wall --确认
```

`tree`：默认主林；运行结果林要显式打开，避免顾问把回当行业世界。  
`/kb`：行业包先画主林；缩写检索走 `别名`。  
`ask`「什么是 X」：对上主林定义；「为什么不能混用 / 不能再乘」走运营已封印链。

变更双胞胎：新主数据字段 = 先主林假设槽再给工匠；新引擎 I/O class = 挂运行结果或 L4，不新开主林根；改工时公式 = 改 `F.l3.sph_and_hours`，不改 SPH 定义。
