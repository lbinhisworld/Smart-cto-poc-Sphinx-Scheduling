> `/kb` 上一块**主题工作台**：待确认认解释链，小白探针问空栏。不是两个站点，不是第四个智能体。  
> 运营怎么生成：[`运营本体生成-升级方案.md`](运营本体生成-升级方案.md)。  
> 行业怎么提取：[`行业本体提取-升级方案.md`](行业本体提取-升级方案.md)。  
> 三角色与 `harvest_complete`：[`封印本体知识库与三角色-升级方案.md`](封印本体知识库与三角色-升级方案.md)。  
> 旧分册（已收进本文）：[`待确认队列-升级方案.md`](待确认队列-升级方案.md)、[`小白探针-升级方案.md`](小白探针-升级方案.md)。  
> 不改 `packages/engine/`，不自动封印，禁止写回约定日，禁止补冷链 / 过敏原 / 机台 APS / 规格没有的工序树。

## 1. 目标

现在点头只在命令行：`python -m kb harvest-check <叶子> --确认`。它只验「有没有从主张通到叶子、人有没有点头」，**不改卡片状态**。顾问只会复述已封印链，树不够密就停。中间缺三截：

1. **认链**：客户在页面上认一条 L1→叶子（或主林构成）解释链，而不是给所有黄卡打勾。  
2. **问栏**：对着打开主题里的空栏 / 断边，用模板笨问题把反例、权责、成立条件问出来，并记下哪句问话改了哪一栏。  
3. **构建期收矿**：你和 Cursor 的对话往往不完整、库也不全。默认先聊完写成方案，再 `@解析员` 提取，最后才让探针扫**这次新链**的空栏。禁止拿聊天记录当出处，禁止聊到一半就改 `kb/`。作业顺序见 §7。

工作台上认链 / 问栏是一条流水线：

```text
打开主题（唯一份点名表）
   ├─ 路径上仍有假设浅卡     → 待确认（认 / 张力）
   └─ 路径上已封印但栏空     → 只进探针（问栏），不重复认整链
        │
        ▼
   问 → 答 → 拒收或解析员写假设
        │
        ▼
   未封链：nods 认（可带 P 号）→ 人另一步封印
   已封改栏：journal 记增量，可选「认这一栏」
```

失败形态：两个「履约四环节」、两套排除规则；把「认这条链」和「这条有没有例外」做成同一个勾；第四个智能体写 Fact；按食品常识补冷库；一点头整链升格；顾问闲问也进日志；聊天或未点头的方案自动入库。

## 2. 原则：共用什么、分开什么

| 必须共用 | 必须分开 |
|----------|----------|
| 主题点名表 `kb/ops/pending_batches.yaml` | 条目单位：链 vs 卡×栏 |
| 最浅未封折叠 | 话术：复述已有句子 vs 空栏模板问句 |
| 排除名单（L4 / 菜单 / coverage / 孤立叶 / 未点名运行结果） | 动作：认·张力 vs 答·拒收 |
| 三轨取链（§5） | 台账：`nods.yaml` vs `probe_journal.yaml` |
| `harvest_complete` 作为「能不能认链」的唯一门 | 已整条封印的链不进待确认；栏空的已封印卡仍进探针 |
| `/kb` 一个主题选择器 | 按钮不共用 |
| 演示角色（计划 / 销售可点头、可取问句） | 写增量 / 写假设只许解析员 |
| 构建期：方案.md 当出处（你认过「这次要建的理解」） | 聊天记录、Cursor 随口实现幻想当出处 |

`POST /api/kb/ask` 闲问默认不建任一队。那种问只复述已封印链。对话中顾问可答已封印的「为什么」；库不全则停，提示先写方案再 `@解析员`，不要当场编卡。

探针**不是**第四个智能体。三角色写权限不变：顾问只读，解析员只写 `kb/` 假设，工匠只接 Ticket。第一期连 `.cursor/agents/` 新文件都可以不做；落地是 `python -m kb pending` / `probe` + 顾问一种「探针」意图（只问队列里那一句）。

## 3. 主题、折叠、排除（共用闭包）

点名，不是扫全库。台账（不是卡片）：

```yaml
# kb/ops/pending_batches.yaml
- 主题: 履约四环节
  轨: 运营
  叶子:
    - F.l3.stg.demand
    - F.l3.stg.schedule
    - F.l3.stg.make
    - F.l3.stg.fulfill
- 主题: 履约主林未封叶子
  轨: 行业主林
  叶子:
    - D.item
    - D.uom
    - D.uom_convert
    - D.bom
    - D.item_route
    - D.wo_task
    - D.wo_task.hours_wall
    - D.wo_task.hours_man
- 主题: 运行结果·插单
  轨: 运行结果
  叶子: [D.insert]
  挂上许可: [F.l3.backward_place, F.l3.fence_ripple]
  说明: 不捎带 D.trace / D.conflict / D.plan_version
```

首屏只打开「履约四环节」。主林与插单等人说「打开这一主题」再进默认列表。禁止在点名表里加菜单、投影、coverage。

共用函数（先写这一份，探针只做投影）：

```text
theme_closure(主题)
  → 点名叶子 + grounding_path（按轨，§5）
  → 去掉排除名单
  → 按最浅未封折叠
  → 返回浅卡 + 被收住的叶子 + 整条路径
```

折叠：同一主题里，多张叶子只差已封印的许可、浅层未封卡相同，**按最浅未封印卡出一条**，下面列出被它收住的叶子。人认的是浅卡这条链，不是把许可再打一遍勾。父卡未封则子卡不进探针。

| 排除 | 理由 |
|------|------|
| 层 = 投影（菜单、模块号、演示角色、`F.l4.*`） | 软件轨，不是客户要认或要问的生意 |
| `kb/coverage.yaml` 行 | 对账台账 |
| `grounding_path` 为空的卡 | 孤立 L3；`harvest_complete` 已拒 |
| 运行结果林整枝 | 除非单独开主题点名 |
| 库外战略、无出处新流 | 解析员不准写，队列更不准列 |

运行结果（`D.insert`、`D.plan_version`、`D.conflict`、`D.trace`…）默认不出。顾问问「怎么插单」停，是因为对象卡未封，不是漏进默认队列。

### 3.1 入队分叉（同一闭包，两种队列）

```text
theme_closure(主题)
   ├─ pending_items：路径上仍有假设浅卡 → 待确认
   │     已整条封印的链不进待确认
   └─ probe_queue：对闭包路径上的卡查空栏 / 断边
         ├ 未封浅卡的空栏     → 先问，问完再进待确认认链
         └ 已封卡的空栏       → 只问、只记 journal，不重复认整链
         停机三件已齐、或日志已「已问/已答」等解析员 → 不出新问句
```

履约四环节示例：

| 去向 | 锚点 | 原因 |
|------|------|------|
| 待确认 × 4 | `F.l3.stg.demand / schedule / make / fulfill` | 最浅未封环节 |
| 探针（浅卡） | 同上四张，若栏空 | 先问再认 |
| 探针（已封改栏） | `F.l1.mto_no_fg_stock`、`F.l1.board_is_meter`、`F.l1.crew_in_sph` | 已封印，缺何时成立/不算 |
| 两边都不进 | `F.l3.due_change_via_approval` | 已封且栏较齐；已被 demand 收住 |
| 两边都不进 | 未点名的 `D.insert`、`F.l3.menu_*` | 排除名单 |

`pending_items` 与 `probe_queue` 禁止各写一套点名或折叠。新增主题 = 改点名表 + 加测试，不加新 L3 根。

## 4. 待确认：认一条解释链

一条条目：

```text
主题批次
  └ 浅卡编号
       └ 链：L1 → … → 浅卡          （运营）
         或：已封印对象根 → 属于… → 浅卡   （行业主林）
         或：运行结果根 + 挂上的运营许可   （仅显式主题）
  收住的叶子: […]
  话术：顾问同款（卡上已有句子）
  动作：认 / 有张力（须选层）
  探针: [P.xx]     # 可选；这条理解来自哪句问话
```

履约首批（最浅未封是四个环节）：

| 主题 | 最浅未封 | 链（到主张） | 收住的叶子 |
|------|----------|--------------|------------|
| 履约四环节 | `F.l3.stg.demand` | 按单零仓 / 交期锚 → 履约流 → 需求环节 | `due_change_via_approval`、`normalize_to_board` |
| 履约四环节 | `F.l3.stg.schedule` | 同上 → 倒排环节 | `backward_place`、`fence_ripple`、`sph_and_hours`… |
| 履约四环节 | `F.l3.stg.make` | 同上 → 制成环节 | 报工/回池等支撑假设 |
| 履约四环节 | `F.l3.stg.fulfill` | 同上 → 履约关闭 | `soft_conflicts` |

点过头、尚未封印：状态写「已点头，待封印」。顾问在封印前仍视假设为缺前提。

话术复用顾问：运营用「从交付模式上看 / 因此从权责上看 / 所以…」；行业主林用「从对象上看，…；因此槽是…」。不要新写问卷题干。

**已封印卡只改栏，不走本条认链。** 给 `F.l1.mto_no_fg_stock` 补「何时不算」不要让人再认一遍交期链。见 §8.2。

## 5. 三种链（程序怎么取路径）

现成 `grounding_path` 只认运营「主张」层。行业对象没有主张，硬套会得到「没有从主张到叶子的边路径」。待确认与探针共用分轨，不要把行业卡伪造成 L1。

### 5.1 运营链（默认）

沿用 `roles.grounding_path`：撑住谁 / 属于 / 论证前提，向上找到层=主张。  
`harvest_complete` 原样复用。

### 5.2 行业主林链

不找主张。从叶子沿 `属于` 走到主林根（订单 / 版 / 组 / 工单 / 品项 / 计量 / SPH）。  
进待确认门槛（同时）：叶子在行业方案 §8.1「能讲履约」清单或该批点名表；路径上至少一张仍为假设；根已在主林。

探针在主林上只问定义 / 属于或独立 / 别名，不问「谁有权」。

顾问「什么是 X」仍只讲已封印定义；主林点头未封印之前，闲问继续缺前提。

### 5.3 运行结果链（仅显式主题）

默认空。主题必须同时点名运行结果叶子（如 `D.insert`）和挂上的运营许可（如 `F.l3.backward_place` / `F.l3.fence_ripple`）。  
展示两段并排：对象定义 + 倒排许可命题。禁止只丢一张 `D.insert` 让人勾。默认只认点名叶子，不捎带五幕 / 冲突 / 差异。

## 6. 探针：问一个空栏

扫描浅、可重入、不产生答案。问句由空栏名 + 卡上已有命题/定义拼模板，**禁止模型编行业故事**。

### 6.1 探针栏（不新开英文槽）

对照 `kb/schema.yaml` 已有中文栏。空了才入队。

| 层 | 空了才扫进来 | 第一期仍不扫 |
|----|--------------|--------------|
| 主张 | 何时成立、何时不算、失败长什么样 | 「为什么没成品仓」的下一层 why |
| 权责 | 撑住谁、持有/可以/禁止、绑哪个对象 | 演示登录账号 |
| 价值流 | 撑住谁、其下 | 再开第二条流 |
| 环节 | 属于、谁有权、其下或说明是否写缺口 | 把环节拆成更多站 |
| 节点/许可 | 属于、撑住谁、绑**最小槽**、何时触发或禁止 | 公式、BR 全文 |
| 行业对象/槽 | 定义、属于或独立、缩写的别名 | 金额、客户、冷链、完整工序 |
| 运行结果 | 仅显式主题点名 | 默认整林 |
| 投影 / 菜单 / coverage | — | **永不入队** |

运营问「何时不算 / 谁有权 / 撑住谁」。行业问「独立还是 A 的 B / 关联还是构成 / 别名」。不要用同一套 Why 去审 `D.board`。问 `D.sph` 与问 `F.l1.crew_in_sph` 必须分锚。

### 6.2 问句模板

只许用：卡名称、命题或定义的前半句、空栏名。禁止插入库外名词。

| 空栏 | 模板 |
|------|------|
| 何时成立 | 「〔名称〕是不是所有订单都这样？什么情况下才算？」 |
| 何时不算 | 「〔名称〕有没有例外？内部返工 / 无约定 / 别的口径还算不算？」 |
| 谁有权 | 「〔名称〕打架时谁说了算？系统能不能代做这一步？」 |
| 撑住谁 | 「不做〔名称〕，坏的是哪条已有主张？指到编号。」 |
| 绑哪个对象 | 「〔名称〕落在哪个最小槽？不要只指到父对象。」 |
| 属于（边断） | 「〔名称〕属于哪一站 / 哪条流？还是不该挂在这里？」 |
| 定义（行业） | 「离开本厂编制，〔名称〕还能不能被指认？它是独立事物还是谁的格子？」 |

倒排的本厂理由走已封印主张（无成品仓、交期锚），不用保质期/冷链解释倒排。

### 6.3 深度（三轴触顶即停）

换层或换卡 = 新 P 号，不是同一轮追问。

```text
一轮 = 1 个锚点 + 1 个探针栏 + ≤2 句口语
        ├ 第 1 句：队列模板（可略改口，不准换锚、不准换栏）
        └ 第 2 句：仅当答非所问，澄清一次
禁止第 3 句。同一张卡最多 3 个栏。
```

本轮不爬层。专家答到另一层，只记「建议下一锚」，等下一轮扫描。

| 限额 | 值 |
|------|-----|
| 每主题同时在问的未封锚点 | ≤ 最浅未封条数（履约四环节 = 4） |
| 栏空的已封印主张 | 第一期 ≤ 3 |
| why 的 why | 0 |
| 库外词 | 立即停，拒收，增量必须空 |
| 新节点 | 0；只填空栏/缺边 |

**停机三件**（运营卡退出探针）：能指到主张；「何时不算」有一条或写明「规格未给反例，缺口」；「谁有权」挂到 L2 或环节。  
行业卡停机：定义能离开编制被指认 + 属于/独立/关联已写 + 缩写已进别名（若有）。

`F.l3.stg.fulfill` 说明已有缺口：只确认「不建出货/催收许可」，不追 why。

### 6.4 何时再扫

以变更触发为主。`ask` 不必全量扫描。

| 何时 | 做什么 |
|------|--------|
| 人打开/关掉主题 | 重算 `theme_closure` → 两队 |
| 解析员写入假设或改边 | 已填的出探针队；新卡仅落在打开主题才入队；边变则待确认须重认 |
| 人点头 / 封印 | 停机三件齐了的出探针；已整条封印的出待确认 |
| 工匠改引擎且补了 coverage | 只扫被挂到的那张卡 |
| 日终/CI（可选） | 队列 diff，抓人手改 YAML 未走日志的漂移；不自动开主题、不自动深问 |

## 7. 构建期默认作业：聊 → 方案 → 解析员 → 探针

对话不完整、库也不全时，**不要**中途收矿，也**不要**先放小白。默认顺序如下。这是作业纪律，不另开代码批次。

```text
你和 Cursor 聊
  （顾问可穿插已封印问题，但不写库；缺前提则停）
        │
        ▼
形成方案.md
  你认：这是这次要建的理解
  拆开：生意约束 / 格子量纲 ≠ CLI、API、页面批次
        │
        ▼
@解析员 对着方案提取
  · 出处 = 方案 + 规格/纪要，不是聊天记录
  · 先交 L1→叶子对齐提案，此时还不写 kb/
  · 路径 A：旧主张撑住 → 只挂新叶子到已有环节
  · 路径 B：打架 → 张力，停；禁止叫探针补被拒的故事
        │
   你点头 = 理解对齐（方案 ≠ 入库许可）
        │
        ▼
写入假设 + 边
  新叶子点名进当前主题，或新开主题（真新生意）
  仅软件做法（接口、测试名单）不进树，留在方案正文 / L4
        │
        ▼
@探针 / python -m kb probe
  只扫「这次新链 ∪ 打开主题」上的空栏
  没有空栏 → 回「这次没有可补的栏」，不准再发明问题
        │
        ▼
接 §8：未封链进待确认认；已封改栏只记 journal
改引擎另开工匠 Ticket
```

### 7.1 方案里哪些可收

| 方案里的句子 | 进哪 | 不进 |
|--------------|------|------|
| 生意约束、谁有权、何时不算 | 运营假设卡 | — |
| 格子、量纲、缩写 | 行业主林 | — |
| 一次排程才有的信封 | 运行结果林（须点名主题） | 默认履约主题 |
| CLI / API / 页面批次 / 测试名单 | 方案正文；需要时 L4 投影 | 主张、待确认、探针 |
| 方案里已删、或仅出现在聊天里的冷库/过敏原 | — | **拒收** |

出处可以写方案路径，但禁止「因为本方案写了所以成立」的循环证明。必须还能指回规格、纪要或你确认过的客户原话。

### 7.2 三个不要

1. **不要拿聊天当出处。** 解析员只收方案里你认过的句子，外加规格/纪要。Cursor 随口说的、方案里删掉的，一律不写。  
2. **不要方案一写完就自动改 YAML。** `@解析员` 仍先给人看链，你点头再写。  
3. **路径 B 张力之后不要叫小白。** 探针会把「自动改交期」问成可收缺口。张力先结案（最快日 / 审批 / 拒收），再决定还要不要提取。

「小白有没有要补充的」= 跑 `probe_queue`，不是开放访谈。问句仍用 §6.2 模板，深度仍守 §6.3。新叶子若尚未点名进主题，先改 `pending_batches`（或挂进已有环节的 `其下`），再扫。

### 7.3 和顾问怎么穿插

聊的过程中可以 `@顾问` 问已封印的为什么。库不全、对不上槽，顾问必须停，并说「先把这次理解写成方案，再 `@解析员`」。这不是信号「先猜一张卡」。

实现问题（函数怎么写、页面放哪）不切解析员、不切探针。

## 8. 从问到认到封印

```text
打开主题
        │
        ├─ 未封浅卡（可先探针问空栏）
        │         │
        │         ▼
        │   专家答
        │    ├ 库外 / 击穿 BR-27 → journal 拒收，增量空，不进待确认
        │    ├ 理解不对         → 待确认「有张力」+ 断在哪一层
        │    └ 可收             → 解析员写假设 + journal 增量（出处加 #P.xx）
        │                          → harvest_complete 过门
        │                          → nods 认（可带探针 P 号）
        │                          → 人另点「封印本条」
        │
        └─ 已封卡只改栏
                  → 可收则 journal 增量 + 可选「认这一栏」
                  → 不走封印本条，不改已封印命题本身（只补空栏）
                  → 若改的是边且 grounding_path 变了：作废该叶子旧「认」，新 P 号，未封链须重认
```

`内部返工` 只让交期锚不适用，不是 BR-27 例外。禁止写「不受 BR-27」。  
专家讲出冷库、保质期、过敏原、茶饮渠道：拒收，解析员不准写卡。

### 8.1 认链与封印（两步、两个接口）

```text
解析员交出假设链（可来自探针）
        │
        ▼
待确认展示整条链（人话 + 编号 + 可选 P 号）
        │
   ┌────┴────┐
   认        有张力
   │         │
   ▼         ▼
写入 nods    只记断裂层，停
（不改状态）  解析员另写假设链
   │
   ▼
人另点「封印本条」
   │
   ▼
只把本条路径上「假设」改成「已封印」
禁止改路径外的卡，禁止改 L4，禁止改 engine
```

`harvest_complete(leaf, confirmed=True)` 仍是「能不能认链」的门。页面点「认」= 同一函数 `confirmed=True` 之后**追加 nods 行**。函数本身不改卡片状态。

封印必须同时满足：

1. nods 里该浅卡已有「认」；  
2. 当前 `grounding_path` 与点头时记录的链一致（边若被改过，要重新认；旧 P 行冻结，另开新号）；  
3. 只写路径上的卡。

禁止：点头接口顺手封印；封印接口不查 nods；一次请求批量封印多个主题；用 journal 状态代替 nods 当封印门。

### 8.2 已封印改栏（轻量，不认整链）

给已封印主张补「何时不算」：

- 不进待确认认链，不走「封印本条」；  
- journal 记改栏增量；  
- 可选「认这一栏」：只记账，不改卡片 `状态`（已经是已封印）；  
- 禁止借补栏改已封印命题原文。要改命题 = 张力 + 解析员另写假设链，按未封流程走。

不要对已封印主张跑 `harvest-check --确认` 来冒充认链。那扇门留给未封叶子。

### 8.3 张力 ≠ 拒收

| 专家反应 | 记哪本账 | 下一步 |
|----------|----------|--------|
| 冷链 / 过敏原 / 自动改约定日 / 无出处 | journal **拒收**，增量空 | 不进待确认 |
| 「这层理解不对」 | nods **张力** + 断在（主张 / 权责 / 价值流 / 环节 / 许可 / 对象） | 解析员另写假设链 |
| 正常补栏或补边（未封链） | journal 已收假设 → nods 认（带 P 号） | 人另一步封印 |
| 正常补栏（已封卡） | journal 已收假设；可选认栏 | 不封印 |

## 9. 两本台账

都不是卡片，不进 `tree` / `prove`。交叉引用，不合成一张大表。

### 9.1 `kb/ops/nods.yaml`（认链）

```yaml
- 叶子: F.l3.stg.schedule
  链: [F.l1.due_is_shared_reality, F.l1.mto_no_fg_stock, F.l3.vsm.order_to_delivery, F.l3.stg.schedule]

  何时: 2026-09-21
```

认栏（已封卡，可选）另用：

```yaml

  栏: 何时不算
  主题: 履约四环节
  结果: 认栏

  谁: 计划
  何时: 2026-09-21
```

`结果: 认栏` **不能**当「封印本条」的前提。

### 9.2 `kb/ops/probe_journal.yaml`（问句 → 增量）

```yaml
- 编号: P.20260921-03
  何时: 2026-09-21
  主题: 履约四环节
  锚点: F.l1.mto_no_fg_stock
  探针栏: 何时不算
  小白问: 按单、没成品仓——内部返工还要从约定日倒排吗？
  专家答: 内部单没有客户约定，交期锚这条不算；不是BR-27例外。
  出处纪要: 客户会议反馈/内部返工口头说明.md
  库外: false
  增量:
    新卡: []
    改栏:
      - 编号: F.l1.mto_no_fg_stock
        栏: 何时不算
        从: []
        到: [内部返工]
    新边: []          # {种: 撑住|属于|关联|是一种, 从, 到}
  叶子: F.l1.mto_no_fg_stock
  状态: 已收假设      # 已问|已答|已收假设|已点头|已封印|拒收|认栏
  拒收理由:
```

卡片回指沿用「出处」：

```yaml
出处:
  - 斯芬克斯-排程服务POC-开发需求规格.md
  - kb/ops/probe_journal.yaml#P.20260921-03
```

边的增量只记：`撑住` / `属于` / `关联` / `是一种`。不要写 `DRIVES`。

硬规则：

1. 「已问 / 已答」必须灰显「尚未入库」。  
2. 增量只能由解析员在写 `kb/` 的同一次提交里填。禁止聊天框自动 diff。  
3. GUI 不能写封印库。POST 只许 APPEND `nods` / `probe_journal`。  
4. L4 / 菜单 / coverage 不进增量、不进 nods。  
5. 主产物常常是改栏，展示必须并排：改了哪一栏 / 多了哪条边。拒收也进时间线。

## 10. `ask` 怎么跳

询问区保持只读顾问。缺前提时：

| 对上什么 | 跳到哪 |
|----------|--------|
| 打开主题里的**未封浅卡** | 「去待确认认这条链」 |
| 打开主题里**已封但栏空** | 「去探针问这句」 |
| 对不上打开主题 | 只报缺前提，**两边都不自动建队** |

不要从 `ask` 的闲聊自动追加 P 号。

## 11. 页面：一块主题工作台

`/kb` 已有行业树、运营树、顾问询问。加**第三块「主题工作台」**，不要第四个孤岛，不要独立问卷站。

- 顶上一个主题选择器（默认履约四环节）。  
- **上栏待确认**：浅卡、链编号、顾问话术、认 / 有张力；已点头灰显「已认」，Q 批以后出「封印本条」。  
- **下栏探针**：可问清单（锚点、空栏、模板问句）+ 时间线（问句 → 改栏/新边 → 状态）。  
- 点编号跳到已有卡片详情。出处含 `#P.xx` 时显示「由探针 P.xx 补了某栏」。  
- 来自探针的待确认条展示 P 号。

角色与演示登录一致。谁能点头、取问句：计划 / 销售演示。谁能封印、写增量：更窄，或仅本机开发会话。POC 不做客户账号。

解析员：写 `kb/` 假设链、点名表、journal 增量；不点头、不封印。  
顾问：只读；探针意图只吐队列一句；张力 / 已问由页面记台账。  
工匠：无。改 `/kb` 才开 Ticket（绑「主题工作台」，不是绑 `so_order.due_date`）。

## 12. 生成顺序

不要先做聊天 UI，不要先写第四个 agent，不要先写第二套折叠。  
构建期作业（§7）是纪律，不占 Q/P 编号：聊完先写方案，再 `@解析员`，再 `probe`。

```text
1. theme_closure + pending_items（点名 → 验链 → 折叠 → 排除）     【Q0】
2. probe_queue = 同一闭包上的空栏/断边 + 模板问句              【P0】
3. CLI：python -m kb pending | probe [--主题 履约四环节]
4. GET /api/kb/pending 与 GET /api/kb/probe 只读
5. /kb 主题工作台两栏只读
6. probe_journal + 解析员手填增量
7. nods + POST 认/张力/认栏（不改卡片状态）；nods 可带 P 号
8. 封印本条（另接口；须 nods「认」且链未变；认栏不够）
9. 顾问提示词补「探针」意图（可不新 agent）
10. （更后）现场访谈才考虑 .cursor/agents/probe.md
```

## 13. 批次

| 批 | 做什么 | 验收 |
|----|--------|------|
| Q0 | `theme_closure` + `pending_items` | `menu_kb` 不进；履约四环节进 4 条浅卡；未点名 `D.insert` 不进默认主题 |
| P0 | `probe_queue` 复用 Q0 闭包 | 四张环节可因栏空入探针；`due_change_via_approval` 不入默认队；`mto_no_fg_stock` 因缺「何时不算」入队 |
| Q1 | CLI `pending`；GET `/api/kb/pending` | 与 Q0 同一函数；只读 |
| P1 | 模板问句；禁止词表 | `mto_no_fg_stock` 问句不含冷库/保质期 |
| P2 | CLI `probe`；GET `/api/kb/probe` | 与 P0 同一函数；只读 |
| Q2 | `/kb` 工作台上栏待确认只读 | 能看到「从交付模式上看…」；询问页不回归 |
| P3 | 工作台下栏可问清单只读 | 与上栏同一主题选择器 |
| P4 | `probe_journal` schema | 拒收则增量空；已问不得出现改栏；增量编号必须在库中 |
| P5 | CLI `journal`；出处可回指 `#P.xx` | `ask` 仍不因日志写库 |
| P6 | 工作台时间线只读 | 一行能看出问句→改栏；拒收行空白 |
| Q3 | `nods.yaml` + POST 认/张力/认栏 | 点头后 YAML 状态仍是假设；`认栏` 不能触发封印；`ask` 未封环节仍缺前提 |
| Q4 | 「封印本条」 | 须 nods「认」且链未变；L4 与路径外不变；无台账或仅「认栏」则 403 |
| Q5 | 打开主题「履约主林未封叶子」 | 顾问「什么是墙钟 / BOM」在封印后不再缺槽 |

| P7 | 顾问「探针」意图 | 只问队列句；原理切回 `ask` |

Q0 未绿，不写 P0。Q3 未做，探针不准发明第二扇点头门。Q4 未做之前，封印仍：人点头后另嘱解析员改状态（禁止模型自己升格）。

## 14. 怎么测、怎么用

```bash
pytest -q tests/test_kb_*.py
python -m kb pending --主题 履约四环节
python -m kb probe --主题 履约四环节
python -m kb journal
python -m kb harvest-check F.l3.stg.schedule --确认
python -m kb ask "谁能改交期" --角色 销售
```

测试必须锁死：

- 投影 / 菜单 / 无路径叶子 / 未点名运行结果：两队都不进。  
- 倒排环节下多张许可：待确认一条浅卡，探针不拆子许可。  
- 已整条封印的链：不进待确认；其上栏空主张仍可进探针。  
- 模板问句不含：冷链、冷库、保质期、过敏原、茶饮、机台 APS。  
- journal「拒收」增量三个列表皆空；「已问」不得出现改栏。  
- nods「认」之后抽一张路径卡，状态仍是假设（Q3）。  
- 仅「认栏」、无「认」：封印接口 403（Q4）。  
- 写增量后 `consult` / `ask`：假设仍不得当前提。

## 15. 第一期人工试跑（不改代码也可做）

打开主题「履约四环节」，先问栏空主张，再谈认链：

1. `F.l1.mto_no_fg_stock` / 何时不算：「内部返工还要从约定日倒排吗？」→ 已封改栏，只记 journal。  
2. `F.l1.crew_in_sph` / 何时不算：「SINGLE 口径的组，还要不要把人数乘进去？」  
3. `F.l1.board_is_meter` / 何时成立：「备货单、样品单也必须先说到版吗？」  
4. `F.l3.stg.fulfill` / 缺口：「出货温控、回款催收——记缺口还是另开一条流？」期望：记缺口，不建许可。  
5. 负例：「做早了冷库会不会爆？」期望：拒收，不入库、不进待确认。

试跑只记纪要。人点头后才叫解析员写假设。禁止模型听完负例就补冷链卡。四个环节的「认」仍按待确认话术，不和上面 1–3 混成一个勾。

构建期试跑（对照 §7）：先把某一段需求收成短方案 → `@解析员` 只交对齐链、先不写卡 → 你点头后再写假设 → `python -m kb probe` 只应出现这次新链上的空栏。路径 B 的假需求（自动改约定日）不得进入探针队。
