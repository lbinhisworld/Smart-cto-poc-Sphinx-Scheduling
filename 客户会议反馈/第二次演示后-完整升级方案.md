## 3. 原则

1. **按他们正在用的表仿真。** 计划、未排汇总、报价、品控，群里已经给出的表头按原列名、原列序导出。没有表样的，用本文默认列，表到了再改列，不改算法。
2. **排程继续组×天倒排。** 先成品、后半成品（BR-34）。冲突只提示（BR-50）。做不到就停，并给出最快可完成日（BR-47）。导出和统计不触发重排（BR-40）。
3. **交期只有人能改。** 最快方案、项目完成日、商机预计成交日、关键路径延期，都不写 `so_order.due_date`。
4. **数量先到版，工时走现有函数。** 领料、待排料走 BOM 与换算链（BR-01、BR-03）。墙钟与人·时分开；`CREW` 口径不在墙钟之外再乘人数（BR-11、BR-12）。
5. **进度和明细分开授权。** 能看见这一行的人，都能看见每一列走到哪。例外：研发看不见对客报价这一列。点开的金额和正文由接口删掉，不靠页面藏。
6. **追溯读金蝶已经倒推的用量和批次。** 原料不在报工里重录。本系统不做标准 backflush，避免和 [工艺口径与量产成本隔离-升级方案.md](工艺口径与量产成本隔离-升级方案.md) 里「禁止用标准倒挤掩盖工序浪费」打架。
7. **人员级排班单独评估。** 本轮派工单的「生产人员」留空。计划给出人数和人·时，名单由生产填。不把「4 个人一天 10 小时用不同品项填满」写进倒排。
8. **待定未签字，不改 `packages/engine/` 的排程循环，不改 `GroupCode`。** 包 A 的 what-if 复用现有 `schedule()`。包 C 的金额用已有人·时和费率。工序树、设备清单没到之前，不做 F4 归集测试。

## 4. 包 A · 计划能拿去作业

算法以 [派工领料与待排负荷-升级方案.md](派工领料与待排负荷-升级方案.md) §3–§5、§7、§11 为准。下面只写对外口径和 9/22 补上的两块。

### 4.1 派工单与领料

下到产线的文件只来自已发布计划。未发布的试排可以导出，计划版本和「未发布，不得下发」写在页脚。这三行表头不写这两句。

2026-09-23 计划发来的表头与规格十列不是同一份。派工单按这张表，只出一张，不再另附领料表。表题是《模具组》生产排程这种短名，不带「一部·」。第二行左侧是「组长：」，右侧是「生产日期：」。列序与底色固定为：`生产人员 | 班别 | 型号 | 品名 | 枚/版 | 单位 | 订单需求量 | 单据编号 | 购货单位 | 巧克力颜色 | 气泡垫 | 真空袋/内衬 | 回料袋颜色 | 单位 | SPH | 人力/人 | 计划盒数 | 实际生产 | 生产工时 | 累计工时 | 备注`。组名用中文，表内不出现 `MANUAL`、`MOLD`。

能从现有主数据填的才填：班别、型号、品名、枚/版、订单单位和需求量、单据编号、购货单位、巧克力颜色、SPH、人力、计划盒数（版数 ÷ 版/盒）、生产工时、累计工时。生产人员留空。气泡垫、真空袋/内衬、回料袋只在 BOM 子件名称对得上时写入名称，对不上就空着。第二个「单位」、实际生产没有记录时也空着。不编包材颜色，不编包材数量。

同一工单各日领料相加等于整单毛需求，这条仍只用于齐套和待排缺口，不再拆成第二张领料表。给产线的是毛需求口径，净需求仍只在齐套和排程里用。
- 「生产人员」留空。系统只有 `crew_plan`，没有这一班是谁。
- 客户要原料或包材的公斤、采购单位时，等换算和清单确认后再加列。本轮单位是版。

日产能盖不住整单时，按现有倒排把剩余版数排到后面的工作日。演示时用「日产能 500、订单 5000」这句把这件事说出来。

### 4.2 最快方案

仅当本轮倒排未安置完，或半成品赶不上，且最快可完成日晚于客户交期时，才生成方案。

方案是一次 what-if：锚改成当次算出的最快可完成日，这个日期只活在提案里；仍用现有倒排；范围只含这一张订单；不发布，不替换当前计划。页面标题写「提案 · 未改交期 · 未下发」。

销售能转述的事实全部来自这次试排：原交期、建议不早于哪一天、卡在未安置还是半成品来不及、提案上的组与各日版数、墙钟与人·时、整单领料。协商待办里带三句：建议交期、要做几天、主要用料。销售回确认日之后，生管改锚再排，仍走交期协商方案。试排在最快日上仍然排不完时，写明「最快日试排仍未排完」，不把失败试排说成已经可做。

### 4.3 未排订单汇总

领导要的是一张能导出的表：手上还有多少订单。对外用客户的三类，对内仍保留派工方案的三格，避免把「在池子里」说成「已经排完」。

| 对外（导出与口头） | 对内判定 | 料和工时 |
|--------------------|----------|----------|
| 已下单未排 | `schedule_phase = PENDING`，从未进入当前计划 | 整单毛需求；工时标「需求工时，未落到日期」 |
| 在制 / 在途未排 | 已有报工或半成品入库，但下道或剩余数量不在当前计划里 | 只算还没排的那一段，已完工的料不重复加 |
| 只排了一部分 | 当前计划已有该单任务，同时仍有未安置余量，或报工尾数已回池 | 只算剩余版对应的毛需求与需求工时 |

内部第三格「池内未跑完」（人已选进排程池，这一轮还没有任务，或有未安置红）不叫已排产，导出时并入「只排了一部分」或「已下单未排」，随它有没有历史任务而定。驾驶舱三个数与这张表对得上。

待排缺口仍按派工方案 §5.2：待排订单按交期从早到晚，用一次库存快照依次占用。各单短缺禁止相加。展不开的订单单独计数。曹应凤的表样到达后，列序改成那张表，三类口径不改。

### 4.4 半成品完成

曹应凤现在靠二部入库数量手工改 Excel，才知道哪些单可以排下道。订单视角的排程看板上，半成品报工完成量达到计划量时换一种颜色，并标完成数量。齐套仍读库存快照；库存以金蝶为准，本轮用现有同步或样本，不在这里另造仓库。

这是包 C 在产品的数量切片。原料仓到在制再到入库的整段状态机，等生产会签节点名（原 F-TBD-09～12）后再做。

### 5.1 手机 · 去拜访

销售只进这一页，不先选客户、不先选商机。

1. 点「去拜访」，按住说话或打字。语音先转成文字，和手打走同一步整理。
2. 大模型只出草稿：客户名、现有客户还是陌拜、发生了什么、成果、下一步、下一步日期。成果用三个：关系建联、触达决策人或决策链、挖到商机。挖到商机时草稿里多一行商机名称。
3. 销售点确认后才写入。未确认的草稿不进时间线，不进有效拜访，不进分布表。
4. 客户关联在同一张草稿上。名称对上已有客户，标出将写入谁的时间线，销售确认。对上好几家，列出两三家让他点。对不上，问要不要新建；确认后建立客户，并把这次拜访写进该客户的时间线。
5. 确认后若草稿里有商机名称，才建商机并挂上这次拜访。不从一段话里自动落单。

拜访分成现有客户和陌拜。陌拜不强制先有客户，先记签到，事后再补名称。签到、签退都记时间。两者相差不满 15 分钟仍可确认保存，标成无效拜访，不计入目标完成数。15 分钟是销管口头口径，先当演示默认值。位置和照片本轮用模拟字段，不接真 GPS、不接水印相机。

每个客户一条拜访时间线。首页那三条建议来自时间线加一张 SOP，不靠模型自由发挥：上次是建联，下一步就是约见决策人；已经见到决策人，下一步就是问是否打样；已经挖到商机，下一步就是补打样或报价。超过下一步日期的标黄，排进这三条。一点建议就回到「去拜访」，并带上这个客户。

目标用四项，种子或手填，每个销售看自己的目标、已完成、还差多少：新客、有效拜访、商机、签单。销管看全员差额。完成数只计已确认且有效的拜访。主管批量导入、自定义指标拖拽，本轮不做。

加急或插单时，建议或商机行上能打开 §4.2 的最快方案，标题仍是「提案 · 未改交期 · 未下发」。CRM 里不改订单交期。

大模型做成可配置：地址、密钥、模型名。演示默认 DeepSeek。密钥不进仓库。没配通时，仍可用手打文字走同一张草稿，演示不中断。

主图是分布，不是漏斗。漏斗只留一排总数。行是已确认的拜访成果，列是商机走到哪：

|  | 还没成商机 | 打样 | 报价 | 签单 |
|--|------------|------|------|------|
| 关系建联 |  |  |  |  |
| 触达决策人 |  |  |  |  |
| 挖到商机 |  |  |  |  |

格子里是客户数。点开是名单。销售的动作是「再去拜访」或「补成商机」。销管的动作是点出谁有效拜访低于目标、谁拜访很多但仍停在建联、谁已经见到决策人但没有打样、哪条商机在打样或报价停超过 7 天。

默认只计有效拜访。可切换「全部拜访」，陌拜尚未建客户的落在「还没成商机」，避免转化率被抬高。口径写在图上：分子分母都来自已确认的拜访，草稿不算。

### 5.3 商机行上的单据列

点进某一行之后，仍是单据列，不按角色拆成多页。格子状态由单据推导：没有下一张单据就是未到，有了但未结案就是进行中，样品结案、报价通过、合同生效就是已完成。上一列完成不自动建出下一列的单据。丢单是整行结案，原因用：价格、交期、样品未过、客户取消、其他。A 级由销售总监手标，确认后签单格显示「已转项目」，进入现有项目大盘。B/C 不进项目大盘。项目完成日不写订单交期。

拜访正文在客户时间线上。财务和研发的行上没有拜访正文。业务员、业务助理、销管看得到，过期标黄。

| 列 | 格子上 | 点开之后 |
|----|--------|----------|
| 打样 | 未到 / 进行中 / 已完成，加日期 | 轮次、客户反馈、证据。沿用样品步骤。一行商机可以挂多款。打样成本另见下，不混在证据里 |
| 打样成本 | 同上，无金额 | 研发填的实际打样数量、物料、人工制费。推给财务后，财务才出对客报价 |
| 工时 / BOM | 同上 | 关联品项的 BOM、计划墙钟、计划人·时。没有已发布计划工时的品项写「尚无计划人工」，不估一个数 |
| 内部报价 | 同上 | 计划人工（人·时 × 标准单价）、售价与计划人工的差额。不是打样成本 |
| 对客报价 | 同上 | 财务给到业务的报价 |
| 签单 | 同上 | 合同号、品项、数量、已收 / 待收 |

20 款打样、其中 3～5 款报价、客户选定 1 款下单，都落在同一行的打样列和对客报价列里。打样成本、计划人工、对客报价是三笔数，禁止加总。

## 6. 包 C · 财务这一轮能看的数

财务四条的全量仍按原计划的门槛：工序树没书面确认，不做多工序归集；瓶颈设备清单没确认，折旧不进排程。本轮只把 Kevin 在会末点名的缺口做成看得见的数。

### 6.1 金额差

两条已经有数量的链，补上金额，并排出现：

- 报价：售价、计划人工、差额。只出现在内部报价列，角色见 §5.4。
- 生产：计划人工成本与实际人工成本，以及差额。沿用现有报工和 `hr_labor_rate`。看板上同时保留工时，避免只剩金额或只剩小时。

实际材料、折旧、水电不进这两个差额。打样成本是研发另填的一笔，不并进计划人工差额。打样和失败轮次继续按 Wave X 排除在量产品项成本之外。

### 6.2 商机到项目

销管看转化，用 §5.2 的拜访成果 × 阶段分布。财务这张只数结果，不恢复六段阶段：

- 进行中、成交、丢单各多少
- 成交里有多少被标成 A 级并已转项目
- 转项目之后，项目大盘上立项、采购、试机、投产四格各完成多少

超过 N 天没有下一步的名单仍放在商机大盘，N 默认 7 天。

### 6.3 成功率

演示用两个已有事实，页面上写明口径，不编 ROI：

- 商机成功率 = 成交 /（成交 + 丢单）。进行中不进分母。
- 项目按期率 = 已填完成日且不晚于该节点计划日的格子 / 已到期格子。

合同额、年贡献、打样转量产额作为 ROI 收益（原 F-TBD-02），以及失败打样进项目还是进期间费用（原 F-TBD-03），等财务签字后再做第三个数。关键路径延期只预警，不推销售交期（原 F-TBD-04，默认否）。

Kevin 所说的「在产品管理」先按在制品理解，并在群里确认。本轮与 §4.4 是同一块：订单上能看见半成品完成数量和是否齐套。

## 8. 人员级排班 · 只评估

曹应凤要的是：4 人一组，A 品 3 小时、剩下的小时用 B 品填满，一天按约 10 小时；计划出人力配置，生产填具体名单。总经办补充：只设少数关键岗位，普通岗和包装岗可调动；极端急单仍然受人和模具限制。

这和 Wave 4 的「关键岗人数额度、排完输出组×日人员需求、不点名」不是同一件事。Wave 4 仍按原总计划，等设备与关键岗清单。把不同品项拼进同一批人的剩余小时，是另一项范围，9/22 现场没有承诺。

评估结论在单独沟通后用一页纸回复，两个选项只选一个再报价：

1. 一期停在组×天。派工单给出计划人数和人·时，「生产人员」由生产在表上填写。系统不安排张三某天做哪一单。
2. 二期只做关键岗位名单和人天工时，普通岗、包装岗不进排程。做之前要有关键岗位清单、技能或岗位约束、一天工时口径。没有这些，不写排班测试。

本轮演示若被问到，口径是：现在能告诉生产「这一天这一组要几个人、多少人·时」；具体谁来、怎么把 4 个人的 10 小时填满，等评估结论，不在这次页面里。

组人数如何折成当天产能、排完要加几个人，见 [组人数折产能与加人缺口-升级方案.md](组人数折产能与加人缺口-升级方案.md)。那一份不点名，也不把剩余小时用另一品填满。

## 11. 落地顺序

1. **A1 派工与领料。** 已发布工单导出后，十列（或客户表头）和领料行齐全，各日数量之和等于整单毛需求。
2. **A2 最快方案。** 现有会排红的那张单能开出提案；交期字段与当前计划都不变；销售待办里有三句事实。
3. **A3 未排汇总。** 三类都能列出并导出；缺口是一次占库。
4. **A4 半成品颜色。** 报工完成的半成品在订单看板上换色，并带完成数量。

7. **B3 宽表权限。** 同一条商机按 §5.4 换六个角色。打样成本只出现在研发、财务、总经理的响应里。对客报价不出现在研发的响应里。内部报价金额只出现在财务和总经理的响应里。
8. **B4 A 级转项目。** 项目大盘多一行。加急商机能打开最快方案，标题仍是未改交期。
9. **C 金额差、转化计数、两个成功率。** 与 A4、B3 同一批数据，不另做一套单。
