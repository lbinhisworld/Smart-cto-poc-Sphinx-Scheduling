# M9 品控台账 — 设计说明（落地版）

## 业务规则 BR-QC

| 编号 | 规则 |
|------|------|
| BR-QC-01 | 来料登记与来料异常分表；异常必须关联 `receipt_id` |
| BR-QC-02 | 来料保存时 `supplier_code`、`material_code` 必须存在于主数据 |
| BR-QC-03 | 供应商/原辅料编码以金蝶为准（POC：Mock 同步） |
| BR-QC-04 | 月份/星期/第几周由业务日期服务端计算 |
| BR-QC-05 | 检测保存时按 `config/qc_limits.yaml` 计算 `verdict_computed` |
| BR-QC-06 | 人工覆写判定须填 `override_reason` |
| BR-QC-07 | 附件统一 `qc_attachment` |
| BR-QC-08 | 异常 SLA 超期进待办，不阻断排产（对齐 BR-50 精神） |

## Excel 列映射

### 原辅料来料 `qc_material_receipt`

月份 → `month_key`；来料日期 → `incoming_date`；属性 → `attr`；来料批次 → `batch_no`；保质期 → `shelf_life_until`/`shelf_life_text`；供应商 → `supplier_code`+快照；品名/规格 → `material_code`+快照；数量/单位/备注 → `qty`/`uom`/`remark`。

### 原辅料异常 `qc_material_exception`

关联来料；异常现象 → `phenomenon`；闭环字段 → `status`/`disposition`/…

### 每日异常 `qc_daily_defect`

日期、第几周、发现部门、班次、型号、品名、生产日期、不良数量/分类/具体/内容、处理结果、责任部门、案号 → 表字段；图片 → `qc_attachment`。

### 客诉 `qc_customer_complaint`

客户/项目/产品编码/名称、生产日期、客诉内容与分类、寄样/收样、原因分析、整改措施。

### 审核 `qc_external_audit`

审核日期、类别、类型、不符合项个数、结果、人员、整改回复时间、备注。

### 外来测试 `qc_lab_external_request`

任务接受日期、客户、产品、测试目的/项目、需求部门、报告日期、备注。

### 涂抹检测 `qc_swab_test`

涂抹点/详细点、实验/采样日期、菌落总数/大肠菌群、结果判定、不合格原因。

### 产品检测 `qc_product_test`

客户、产品、采样日期、水分、大肠菌群/菌落总数 cfu/g、判定、不合格原因、备注。

## 配置

- `config/qc_limits.yaml` — 检测合格线、异常 SLA
- `config/integrations.yaml` — 金蝶主数据 Mock 同步开关

## API 前缀

`/api/qc/*`；金蝶主数据 `/api/kingdee/sync-suppliers`、`sync-raw-materials`。
